# 订单、基础资料、BOM、采购与库存一体化设计

> 日期：2026-09-14  
> 状态：业务方案已确认，待按阶段实施  
> 适用范围：订单确认、基础资料、整单 BOM、采购管理、库存管理、收款与后续生产追溯

## 1. 设计目标

本次调整不是引入一套脱离现有图纸和报价系统的通用 ERP，而是把现有业务串成一条可追溯、可人工修正的单据链：

```text
终审图纸 + 对应报价
        ↓
订单确认（TM 主订单）
        ↓
技术明细 / 价格明细 / 单樘实体
        ↓
整单 BOM（规则生成 + 人工增删改）
        ↓
库存核算 / 缺料分析 / 采购 / 领料
        ↓
生产 / 质检 / 发货 / 应收跟踪
```

核心目标：

- 一个客户批次只维护一份订单抬头、交期、收款和交付信息。
- 每种门和每樘实体仍能独立下料、生产、质检和追溯。
- 采购既支持日常备库，也支持订单缺料触发。
- 库存允许人工调整，但所有变化必须形成可追溯单据。
- 自制件按模板和订单规格管理，不为每个尺寸创建一条物料档案。
- 自动生成的数据必须允许业务人员在受控规则下人工修正。

## 2. 已确认的关键决策

### 2.1 单据删除与更正

- 草稿单据可以编辑和删除。
- 已确认、已入账、已发布或已有下游引用的单据不能物理删除。
- 已确认单据采用取消、退货、冲销或新版本更正。
- 界面提供“一键冲销并更正”：自动生成反向流水，并复制一张新的更正草稿。

### 2.2 订单编号

订单主编号按年份生成：

```text
2026 年：TM2600001、TM2600002……
2027 年：TM2700001、TM2700002……
```

编号在数据库事务中生成，并设置唯一约束，防止多人同时创建时重号。

一个客户同一批次的多樘门共用一个 TM 主订单号。不同参数及实体门使用三级编号：

```text
主订单：TM2600001
第 1 种参数：TM2600001-01
第 1 种参数的第 1 樘：TM2600001-01-01
第 2 种参数的 5 樘：TM2600001-02-01 ～ TM2600001-02-05
```

- 主订单号负责合同金额、客户、收款、交期和整体交付。
- 技术明细号负责某一种相同门参数。
- 单樘实体号负责下料、生产、拼装、质检、标签和售后。
- BOM、采购分配、领料、生产、质检和发货均保留 `TM` 来源关系。
- 各业务单据仍有自己的编号，例如 `PO`、`LL`、`FH`、`SK`。

## 3. 核心数据模型

### 3.1 订单抬头 `sales_orders`

建议保留或新增：

- `order_no`：TM 主订单号，创建后不可修改。
- `order_date`、`customer_name`、`project_name`。
- `delivery_address`、`delivery_date`、`salesperson`。
- `subtotal`、`discount_amount`、`total_amount`。
- `received_amount`：由收款分配汇总，不允许直接编辑。
- `outstanding_amount`：`total_amount - received_amount`，实时计算。
- `status`：草稿、已确认、履约中、已完成、已取消。
- `version`：订单变更版本。
- 来源图纸、报价及后续单据的聚合状态。

### 3.2 技术明细 `sales_order_door_lines`

一条代表一种相同参数的门，不因数量大于 1 而复制多行。

摘要字段：

- 明细编号、产品名称、门型、数量、单位。
- 宽、高、开向、材质、颜色。
- 正反门板款式、门框工艺、门套形式、气窗。
- 锁具、正反拉手、开启机构、玻璃规格。
- 图纸任务 ID、终审版本、报价 ID、报价组。
- 业务备注、技术备注、交付备注。

完整技术参数继续保存为冻结 JSON 快照。列表使用摘要字段，BOM 和 DXF 生成使用完整快照，避免为每个图纸参数持续扩表。

### 3.3 单樘实体 `door_units`

订单正式确认后，按技术明细数量展开实体门：

- `unit_no`：例如 `TM2600001-02-03`。
- `sales_order_id`、`door_line_id`、`sequence_no`。
- 当前 BOM 版本、生产状态、质检状态、发货状态。
- 标签、拼装、返工和售后记录均关联实体号。

### 3.4 价格明细 `sales_order_charge_lines`

价格明细与技术明细分开，允许一樘门对应多个收费项目：

```text
TM2600001-01
  不锈钢镀铜门       1 樘
  不锈钢镀铜门套     1 套
  指纹锁             1 套
```

字段建议：

- 关联技术明细，可为空。
- 来源报价 ID、报价项目 ID。
- 项目类型：主门、门套、门框、五金、运输、安装、其他。
- 品名、规格、数量、单位、单价、金额、备注。
- `pricing_mode`：合并报价或拆分报价。

关联报价时自动带入，订单确认前可增删改；确认后通过订单变更单调整，不覆盖原快照。

## 4. 收款与欠款

### 4.1 收款计划使用金额

删除百分比作为主要录入方式，收款节点直接填写具体金额：

- 定金。
- 发货款。
- 其他计划收款。

节点字段：名称、计划金额、计划日期、备注。各节点计划金额总和应等于订单总额；不相等时可以保存草稿，但不能正式确认。

### 4.2 实际收款流水

实际到账创建收款单，例如 `SK26090001`：

- 客户、收款日期、收款方式、账户、凭证号、实收金额、备注。
- 一张收款单可以分配给多个 TM 主订单。
- 一个 TM 主订单可以接收多张收款单。
- 每条分配记录包含订单号、分配金额和对应收款节点。
- 分配合计必须等于收款单实收金额。

### 4.3 欠款发货

- 默认按订单未收金额检查发货条件。
- 未达到发货款要求时阻止普通确认发货。
- 特殊情况使用“授权欠款发货”，填写原因、批准人和预计收款日期。
- 授权仅放行发货，不改变实收金额，欠款继续进入应收列表。

## 5. 基础资料与外部导入

### 5.1 物料分层

基础资料中的物料分为：

1. 原材料：板材、管材、焊材等，参与采购、库存和领料。
2. 标准采购件：锁、插销、花件、玻璃等，参与采购、库存和领料。
3. 自制件模板：门框骨架、门扇骨架、门扇外皮等，用于 BOM 和工序，不按任意尺寸建立库存 SKU。
4. 外协件：可由内部工序或供应商加工，保留发料和回收入库关系。
5. 非库存费用：运输、安装、加工费等，只参与价格或费用核算。

绝大多数骨架和外皮按“自制件模板”管理。订单尺寸、展开尺寸、切割长度保存在订单 BOM 行和生产任务中，不生成新的物料档案。

### 5.2 物料与供应商关系

- 一个内部物料可以关联多个供应商产品。
- 供应商产品保存供应商料号、采购规格、采购单位、换算率、价格和交期。
- BOM 引用内部物料，采购时再选择具体供应商产品。
- 供应商关系不能代替内部物料档案，避免换供应商后历史单据失去含义。

### 5.3 外部 ERP 导入

基础资料增加导入向导，支持 Excel 和 CSV：

1. 选择导入对象：物料、供应商、供应商产品、仓库、库位、期初库存。
2. 上传文件并识别表头。
3. 将原 ERP 字段映射到本系统字段。
4. 预览新增、更新、重复、缺失和格式错误。
5. 选择导入策略：按编码更新、跳过重复、仅新增。
6. 执行导入并生成成功/失败报告。

导入要求：

- 每次导入生成批次号，保存来源文件摘要、操作人和结果。
- 尚未被业务单据引用的数据允许按批次撤销。
- 已被引用的数据只能停用或更正，不能整批删除。
- 期初库存通过专用期初库存单导入，不直接覆盖库存余额。

## 6. 整单 BOM

### 6.1 生成与编辑

订单确认后，根据产品、门型、尺寸和配置规则生成 BOM 草稿。BOM 草稿允许：

- 新增、删除、修改和复制物料行。
- 调整规格、理论量、损耗率、计划量、单位和取得方式。
- 增加锁盒、插销盒、插销、花件及其他遗漏项。
- 删除当前订单不需要的规则生成项。
- 标识来源：规则生成、人工增加、上版复制。

### 6.2 BOM 行类型

- 正式物料：来自基础资料，可采购、入库和领料。
- 自制件：关联自制件模板及生产工序。
- 临时项目：可直接填写名称和规格，用于偶发件。
- 工艺/备注项：不参与库存，仅传递生产要求。
- 费用项：不参与实物库存，可参与成本。

临时项目若要生成采购、库存或领料业务，必须先绑定正式物料，或一键转为正式物料。

### 6.3 发布与版本

- 草稿 BOM 可以直接编辑和删除行。
- 发布后冻结，不允许覆盖修改。
- 更正时自动复制为新版本，例如 V1、V2。
- 新版本发布时计算差异，并提示已经发生的采购、领料和生产影响。
- 未执行的下游需求按差异更新；已经执行的业务使用补料、退料、补购或取消剩余量处理。

## 7. 采购管理

### 7.1 两种采购来源

#### 手工备库采购

- 用户直接新建采购单，不要求关联订单。
- 适用于一次采购大量板材、管材和常用五金，长期逐步消耗。
- 可选择供应商、物料、采购规格、数量、单位、单价、税率、仓库和预计到货日期。

#### 缺料采购

- 来源于已发布 BOM 的净需求。
- 净需求 = BOM 需求 - 可用库存 - 有效预留 - 已覆盖在途数量。
- 支持按供应商和交期合并多个订单需求。
- 采购明细保留多条需求分配记录，但采购单抬头不强制绑定单个 TM 订单。

### 7.2 生命周期

```text
草稿 → 已下单 → 部分到货 → 已完成
                  ↓
                退货/补货
```

- 草稿可以新增、删除和修改物料行，也可以删除整单。
- 已下单未到货时可取消剩余数量。
- 已到货部分不能删除，通过采购退货或入库冲销处理。
- 采购单允许没有订单来源，也允许同时分配给多个订单需求。

## 8. 库存管理

### 8.1 手工库存业务

库存页面提供以下新建入口：

- 其他入库。
- 其他出库。
- 盘点调整。
- 仓库/库位调拨。
- 报废。
- 生产领料。
- 生产退料。

用户不能直接编辑余额。所有增减通过库存单据确认后生成不可修改的库存流水。

### 8.2 余额口径

- 现存量：已经确认入库且尚未出库的实物数量。
- 预留量：已经分配给生产需求、尚未领出的数量。
- 可用量：现存量减预留量。
- 在途量：采购已下单但尚未合格入库的数量。
- 缺口量：需求减可用量、有效在途量后的不足部分。

备库采购入库时不分配 TM 订单。后续生产领料时，库存流水关联具体的 `TM-明细-实体` 编号，实现实际消耗追溯。

### 8.3 更正规则

- 草稿库存单可以删除。
- 已确认库存单不能删除或改数量。
- “冲销并更正”自动产生相反方向的库存流水并复制更正草稿。
- 冲销记录必须关联原单据和操作人。

## 9. 页面设计

### 9.1 订单确认

订单编辑器建议分为六个区块：

1. 订单抬头：客户、项目、日期、交期、地址、销售员。
2. 关联来源：已终审图纸和对应报价单。
3. 技术明细：按不同参数分组展示完整门信息。
4. 价格明细：门、门套、门框、五金及其他收费项目。
5. 收款计划：定金、发货款和其他计划金额。
6. 汇总确认：总樘数、总金额、已收、未收和校验问题。

订单确认页不横向塞入所有技术字段。每条技术明细采用摘要行，点击展开侧栏或详情区查看完整参数。

### 9.2 BOM 工作台

- 左侧按订单、技术明细和单樘实体选择。
- 右侧展示当前 BOM 版本和可编辑表格。
- 顶部提供自动生成、人工加项、批量核验、保存草稿、发布和新建版本。
- 明确显示规则项、人工项、临时项和缺少物料映射项。

### 9.3 采购工作台

- 待采购缺口和采购单分为两个视图。
- 新建采购单可选择“手工备库”或“从缺口选取”。
- 到货进度、剩余量、已退数量和入库状态在明细中展示。

### 9.4 库存工作台

- 顶部显示现存、预留、可用、在途和低库存数量。
- 提供入库、出库、调整、调拨、报废、领料和退料入口。
- 余额、流水和待处理单据分开查看。

### 9.5 基础资料

- 物料、供应商、供应商产品、BOM 规则、仓库与库位使用标签页或二级导航。
- 顶部提供新增、批量导入、导出模板、停用和查重。
- 导入必须经过字段映射、预览校验和结果报告。

## 10. API 与服务边界

建议补充或调整的接口：

```text
POST   /sales-orders                         创建 TM 主订单草稿
POST   /sales-orders/{id}/confirm            冻结订单并展开单樘实体
POST   /sales-orders/{id}/change-orders      创建订单变更

POST   /receipts                             创建实际收款单
POST   /receipts/{id}/allocate               分配到多个 TM 订单
POST   /shipments/{id}/credit-release        授权欠款发货

POST   /master-data/import/preview           解析和预检导入文件
POST   /master-data/import/execute           执行导入批次
POST   /master-data/import/{batch}/rollback  撤销未被引用的导入批次

POST   /bom/{door-line-id}/generate          生成 BOM 草稿
POST   /bom/{id}/items                       人工新增 BOM 行
DELETE /bom/{id}/items/{item-id}             删除草稿 BOM 行
POST   /bom/{id}/publish                     发布 BOM
POST   /bom/{id}/revisions                   从已发布版本创建新版本

POST   /purchasing/orders                    手工或缺料来源采购单
DELETE /purchasing/orders/{id}               仅删除草稿
POST   /purchasing/orders/{id}/cancel        取消未执行剩余量

POST   /inventory/adjustments                创建库存调整草稿
DELETE /inventory/adjustments/{id}            仅删除草稿
POST   /inventory/documents/{id}/reverse     冲销并创建更正草稿
```

具体路径可沿用现有接口命名，以上重点是行为边界。

## 11. 与现有代码的衔接

当前仓库已经具备部分基础能力，应优先复用：

- 已有订单关联终审图纸和报价、订单草稿及确认流程。
- 已有订单行、收款节点和履约生成结构。
- 已有整单 BOM 草稿、人工保存、核验、发布和新版本能力。
- 已有库存流水不可修改/不可删除约束。
- 已有库存调整草稿及确认接口。
- 已有手工采购单、缺料采购、到货检验和采购取消服务。
- 已有物料、供应商、供应商产品、仓库、库位和 BOM 规则基础表。

主要新增或重构点：

- 销售订单编号从 `SO日期序号` 调整为年度 `TM` 编号。
- 将订单抬头、技术明细、单樘实体和价格明细明确拆分。
- 收款节点从百分比录入改为金额，并新增实际收款单与多订单分配。
- 当前采购和库存页面补齐手工新建、草稿删除与冲销入口。
- BOM 工作台补齐人工新增、删除、复制和临时项转物料入口。
- 基础资料新增外部导入向导和导入批次。
- 订单详情补充完整技术摘要和报价拆分项目。

## 12. 实施顺序

### 第一阶段：核心编号与订单模型

- TM 三级编号。
- 订单技术明细、单樘实体和价格明细。
- 报价项目自动带入与拆分/合并显示。
- 金额收款计划及订单详情展示。

### 第二阶段：BOM 人工调整

- BOM 新增、删除、复制、临时项和来源标识。
- 发布版本差异和下游影响提示。
- 保留现有门框加工能力；门框下料规则暂不扩展。

### 第三阶段：采购与库存手工业务

- 手工备库采购完整入口。
- 草稿删除、取消剩余、退货和冲销并更正。
- 库存各类手工单据和流水追溯。

### 第四阶段：基础资料迁移

- Excel/CSV 模板。
- 字段映射、预检、导入批次、错误报告和有限回滚。

### 第五阶段：收款分配与欠款发货

- 实际收款单。
- 一笔收款分配多个订单。
- 欠款发货授权和应收跟踪。

## 13. 验收标准

1. 新订单从 `TM2600001` 起连续编号，跨年自动切换年份且并发不重号。
2. 一个订单可包含多个参数组，每组数量可展开为唯一单樘实体编号。
3. 同一技术明细可选择门和门套合并报价或拆分为多个价格项目。
4. 收款计划只录入金额；实际收款支持一单多次和一款多订单分配。
5. 尾款未收齐时默认禁止发货，授权后可发货但欠款仍保留。
6. 任意尺寸的自制件不会自动创建新的物料档案。
7. BOM 草稿可以人工增删改，发布后只能创建新版本。
8. 采购单既可以完全手工创建，也可以由多个订单缺口合并生成。
9. 备库采购入库时无需绑定订单，领料时可以追溯到单樘实体编号。
10. 库存余额不能直接编辑，所有人工增减均能追溯到库存单据。
11. 草稿可删除，已确认单据只能取消、退货或冲销。
12. 外部 ERP 资料可预览校验后导入，并生成批次结果和错误报告。

## 14. 暂不纳入本轮

- 门框外皮端部异形及完整门框下料规则继续按后续专项完善。
- 完整财务总账、税务发票和银行自动对账。
- 高级需求预测、安全库存算法和供应商自动寻源。
- 3D 下料或三维生产模型。
