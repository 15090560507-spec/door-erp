# 订单、整单 BOM 与轻量 MRP 后续工作清单

更新日期：2026-09-13
当前分支：`feat/semicircle-handles-and-quote-form-improvements`

## 当前已完成

1. 已终审图纸和对应报价可作为销售订单来源，同一订单限制为同一客户。
2. 订单确认采用幂等生成，按数量创建独立门樘生产编号和技术快照。
3. 已建立版本化整单 BOM、自动生成规则、校验警告和发布接口。
4. 门框加工结果可回写整单 BOM；门框具体下料规则按最新要求暂缓完善。
5. BOM 发布后可生成库存需求、采购需求和车间工作包。
6. 工作包支持依赖、物料齐套判断、受控跳过、批量完成和加权进度。
7. 已建立经营管理共用页面组件和当前视口居中的 Portal 弹窗。
8. 订单确认页面已拆分为列表、摘要、整页编辑、来源选择、订单行和履约状态组件。
9. 已新增 `/cutting` 整单 BOM 下料工作台，并替换导航中的旧下料入口。
10. 下料工作台已支持订单/门樘归集、状态筛选、BOM 生成、物料与数量编辑、自动保存后批量核验、版本查看及发布。
11. 已对下料页面增加窄屏单列布局，宽 BOM 表格只在明细区域内部滚动。

## 尚未完成

### P1：经营管理四个工作台

预计 6–10 小时。

- 生产管理：订单进度、工作包、异常和成品质检/入库。
- 采购管理：需求池、采购单、到货和异常。
- 库存管理：全厂库存台账、待入库、待领料和库存流水，不按订单建仓库。
- 基础资料：商品、供应商及其供货关系、BOM 规则模板。
- 统一使用已完成的 workspace 组件，避免横向滚动和黑色散落按钮。
- 权限细分暂缓，后续再恢复“下料仅销售小A可见”等规则。

验收：四个角色工作台共用同一单据链，库存和采购进度来自真实事件，不能手填百分比。

### P1：导航性能与错误治理

预计 2–4 小时。

- 排查效果渲染切换到其他页面时的延迟。
- 重型模块延迟加载并取消无效请求，减少路由切换阻塞。
- 统一接口错误解析，生成失败必须显示具体原因和重试入口。
- 排除 `.next-stale-*`、构建产物和历史目录的 ESLint 扫描。
- 清理现存 React effect lint 问题，重点检查 AppShell、报价历史、库存和渲染模块。

验收：主要导航切换无明显卡顿；局部接口失败不拖垮整个页面。

### P0：迁移、全链路回归与上线

预计 3–5 小时。

- 补历史数据迁移和重复执行测试。
- 真实后端下验证订单新建、保存、修改、确认、失败重试、取消和刷新恢复。
- 验证“订单确认 -> 门樘 -> BOM -> 库存/采购 -> 工作包 -> 质检 -> 成品入库”。
- 检查 1440×900、1920×1080 和 390×844 三种尺寸。
- 最后推送 GitHub，并在腾讯云拉取分支、重建 backend/frontend 容器。

验收：历史数据不丢失，重复操作不产生重复门樘/BOM，核心回归全部通过。

## 建议继续顺序

1. 先做订单确认到 BOM 发布的真实数据回归。
2. 再按实际岗位优先级扩展经营管理四个工作台。
3. 最后集中处理性能、历史迁移和腾讯云上线。

按当前收紧范围，剩余有效开发时间约 11–19 小时；本次整单 BOM 下料工作台的最小可用版已完成。
