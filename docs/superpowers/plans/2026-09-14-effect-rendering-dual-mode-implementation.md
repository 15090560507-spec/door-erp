# 效果渲染双模式实施计划

依据：`docs/superpowers/specs/2026-09-14-effect-rendering-dual-mode-design.md`

## 阶段一：统一任务模型与页面入口

1. 扩展渲染任务存储，加入 `renderMode`、`sourceType`、`sourceSide`、`referenceBindings`、`segmentation`、`componentLayers`、`compositeImage`、`psdStatus` 和 `psdFile`，并为历史任务提供默认值。
2. 将临时参考图与素材库图片都按 `panel`、`trim`、`frame`、`glass`、`hardware` 保存，不再压平为无语义数组。
3. 保留旧接口字段作为兼容输入，将旧“参考款式图”映射为门扇参考。
4. 重构效果渲染页面：移除独立 `LayeredRenderPanel`，增加部件参考区和两个并列生成按钮。
5. 增加任务模式、素材绑定和 PSD 状态展示。

验证：后端兼容性测试、前端 lint/build、现有快速生成回归。

## 阶段二：精准结构来源与合成

1. 抽取现有 `layered_render.py` 的 DXF 图层采集、画布转换、蒙版和合成能力为可复用函数。
2. 系统图纸通过任务参数重新生成 DXF；上传 DXF 直接解析。
3. 为门扇、门框、门套、玻璃和五金生成同画布蒙版与透明基础层。
4. 精准模式按部件调用模型，只传该部件参考；模型结果由服务端蒙版裁切。
5. 按固定遮挡顺序生成最终效果图，保存各部件透明层和合成图。
6. 门框没有独立参考时复用门扇材质结果，避免额外模型调用。

验证：蒙版坐标一致性、参考隔离、最终图尺寸与线稿比例、单部件失败不覆盖。

## 阶段三：普通图片区域确认与局部重生成

1. 新增图片结构识别接口，基于 OpenCV 轮廓和封闭区域生成初始蒙版与置信度。
2. 新增按需加载的区域校对组件，支持彩色预览、点选归类、擦除和补充区域。
3. 保存确认后的蒙版；未确认的图片分割不能提交精准任务。
4. 新增部件重生成接口，沿用原蒙版、画布和其他部件版本。
5. 前端结果区增加各部件“重新生成”操作和当前版本提示。

验证：低置信度拦截、蒙版更新、无关部件像素不变、失败回滚。

## 阶段四：按需 PSD 与旧版清理

1. 新增精准任务 PSD 接口，使用任务已有透明层打包，不调用 AI。
2. 快速任务点击 PSD 时返回“需要转为精准模式”的可执行状态。
3. PSD 按设计文档的九层结构输出，并保持与最终图相同画布。
4. 增加幂等旧版清理，只删除 `layered_render_records.json` 明确引用的文件和记录。
5. 停用旧 `/api/layered-render/*` 路由与前端 API，删除独立面板组件；保留底层 DXF 与 PSD 工具。

验证：按需生成、PSD 图层与透明度、旧文件定向清理、重复启动安全。

## 最终验收

1. 运行后端渲染、线稿、PSD 和数据安全测试。
2. 运行前端 lint 与生产构建。
3. 使用桌面和窄屏浏览器检查页面布局、弹窗居中、按钮状态和区域校对交互。
4. 对系统图纸、DXF、普通图片各完成一次快速/精准流程。
5. 检查 Git 差异，确认未包含日志、备份模板和用户未跟踪文件。
