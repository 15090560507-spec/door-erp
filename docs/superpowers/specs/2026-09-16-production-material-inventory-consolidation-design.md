# 部件生产、装配与库存转换设计

## 目标

将材料准备和加工装配放在同一张生产进度表中，减少阶段切换；同时保持材料、工序和库存三类事实独立记账。整樘门以 `TM` 生产编号贯穿 BOM、领料、加工、装配、质检、成品入库和发货。

## 生产阶段

前台固定为四个阶段：

1. 生产准备：生成、补充、核验并发布 BOM。
2. 部件生产与装配：同屏查看材料状态、部件工序、执行人和整门拼装负责人。
3. 质检入库：成品质检合格后办理成品入库。
4. 发货完成：财务放行、出库、运输和签收。

不再设置独立“物料齐套”页面。后台仍分别保存材料状态和加工状态。采购到货不等于加工完成，工序完成也不能自动虚构材料到货。缺料只阻止依赖该材料的工作包，其他可执行部件继续生产。

## BOM 新增与分类

- 总体“新增项目”保留，用于跨分类补充或暂时无法判断归属的项目。
- 每个分类标题提供“新增本类项目”，新行自动继承分类编码和名称。
- “其他/未分类”只承接导入异常和真正无法分类的项目，不作为日常补充入口。
- 重新生成 BOM 只替换规则生成项；人工新增的锁盒、插销盒、花件及备注保持不变。

## 门框与门套制造方式

固定三种方式，不开放任意组合：

1. 全部分体：门框外皮、门框骨架、门套外皮、门套骨架分别生产。
2. 骨架连体、外皮分体：门框门套共用连体骨架，门框外皮与门套外皮分别生产。
3. 骨架连体、外皮连体：门框门套共用连体骨架和连体外皮。

连体制造项只生成一个工作任务，共用工艺路线、状态和执行人；BOM 中仍保留其包含的产品语义，便于追溯和变更。

## 生产进度表

每一行以 BOM 部件或其工序为中心，展示：部件、材料状态、工艺路线、执行人、计划日期、进度、数量和操作。

典型路线：

- 门框/门套外皮：备料、剪板、折弯、表面处理、完成。
- 门框/门套骨架：备料、下料、焊接、完成。
- 门扇外皮：备料、剪板、折弯、表面处理、完成。
- 门扇骨架：备料、下料、焊接、完成。
- 五金配件：库存已有、采购中、已到货、已备齐。
- 整门拼装：待部件、拼装中、待质检、完成。

整樘门指定一名主要装配负责人，可以登记协作人员；每一道加工工序仍可单独指定执行人，用于进度追踪和计件核算。

## 库存转换

库存只在发生实物责任或存放位置变化时记账，不为每一道加工状态产生库存流水：

1. 原材料领用后进入当前 `TM` 生产单的在制区。
2. 门框、门套、门扇等部件加工完成并实际暂存时，进入半成品仓或半成品库位。
3. 整门拼装领用时，消耗对应半成品和配件，但保留组成追溯关系。
4. 拼装完成后进入待检区；质检不合格进入返工区，不形成成品库存。
5. 成品质检合格后，将整樘门作为一个成品单位转入成品仓，并关联生产编号、客户、规格和组成版本。
6. 发货时从成品仓出库。

## 库存界面

库存页面采用三级结构：

1. 仓库总览：原材料仓、五金配件仓、半成品仓、待检区、成品仓、外协在途卡片。
2. 仓库详情：库区/库位导航和库存明细。成品仓按整樘门展示 `TM` 编号、客户、门型、尺寸、数量、库位、入库时间和发货状态。
3. 库存操作：入库、出库、调拨、盘点和调整集中在详情页或操作抽屉。

没有维护真实货架坐标时不绘制虚拟平面仓库图。总览卡片显示品类数、门樘数、缺货和待处理数量；不同计量单位不汇总成一个无意义的“库存总数量”。

## 一致性约束

- 同一部件不能同时处于半成品可用库存和已被整门拼装消耗状态。
- 只有当前生产版本全部必要工作包完成后才能提交成品质检。
- 只有成品质检合格或明确让步接收后才能入成品仓。
- BOM 版本变更不覆盖已发生的领料、工序、质检和库存流水。
- 手工调整库存必须填写原因并保留不可变流水。
