# 门樘生产履约流程精简设计

## 1. 文档状态

- 设计日期：2026-09-14
- 适用项目：Door ERP
- 设计范围：生产管理、BOM与下料、库存、采购、质检、成品入库和发货之间的流程整合
- 当前运行方式：暂不区分岗位和权限，同一账号可以走完全部流程

## 2. 问题定义

当前门樘履约中心以“生产技术包、执行工作包、供应与仓储、质检与成品、财务与发货、异常、时间线”作为并列页签。这种划分按数据模块组织，而不是按现场执行顺序组织，导致同一事实存在多个入口：

- 生产技术包确认与独立的 BOM 发布重复。
- BOM与下料中的下料执行与生产工作包重复。
- 履约中心的供应、仓储记录与独立采购、库存模块重复。
- 门樘收款与订单确认中的订单实收重复。
- 异常和时间线被当成生产阶段，用户无法直接判断当前该做什么。
- 总进度百分比无法准确说明门樘是否具备进入下一阶段的条件。

本次调整的核心不是减少数据，而是确保每类数据只有一个可写入口，门樘履约中心只负责组织进程、显示阻塞和引导下一步操作。

## 3. 设计目标

生产管理必须让用户打开一樘门后立即看清：

1. 当前处于哪个阶段。
2. 该阶段已经完成什么。
3. 还缺少什么条件。
4. 下一步应执行哪个操作。
5. 相关事实应该在哪个业务模块修改。
6. 历史操作、异常和版本是否可以追溯。

第一阶段不建设岗位工作台、审批流或细粒度权限。所有操作暂由同一账号完成，但事件仍记录操作账号和时间，为以后增加岗位权限保留基础。

## 4. 核心业务边界

### 4.1 唯一数据入口

| 业务事实 | 唯一可写入口 | 门樘履约中心职责 |
| --- | --- | --- |
| 客户订单、金额、收款 | 订单确认 | 只显示已收、未收和发货门槛 |
| 终审图纸 | 图纸终审 | 只显示当前终审版本和文件入口 |
| BOM草稿、核验和发布 | BOM与工艺准备 | 只显示BOM版本、状态和警告 |
| 下料清单、加工图 | BOM与工艺准备 | 只显示是否生成和查看入口 |
| 实际下料、加工和装配 | 生产执行工作包 | 显示当前任务、完成状态和阻塞 |
| 采购单与到货 | 采购管理 | 汇总缺口和预计到货，不重复建单 |
| 库存、预留、领退料 | 库存管理 | 汇总齐套和领料状态，不重复记账 |
| 成品质检与返工 | 生产管理的质检阶段 | 显示检验结论和返工状态 |
| 成品入库 | 库存管理的成品流水 | 显示是否已入库和仓位；办理入库时调用库存模块的同一入库接口 |
| 发货、运输和签收 | 生产管理的交付阶段 | 执行发货并跟踪签收 |
| 异常和操作记录 | 对应业务节点产生的统一事件 | 集中提醒、筛选和追溯 |

### 4.2 BOM与下料的边界

“下料”拆成两个业务概念：

- 下料编制：计算构件、材料、尺寸和数量，生成BOM、下料清单和加工图，属于生产准备。
- 实际下料：车间领取材料并完成切割，登记完成量、余料、废料和异常，属于生产执行。

现有“BOM与下料”页面调整为“BOM与工艺准备”。它负责下料编制，不再登记实际生产进度。该页面作为生产管理中“生产准备”阶段的全屏明细页，不新增顶级导航项。BOM发布后，系统依据工艺路线生成“实际下料”等执行工作包。

### 4.3 生产技术包的处理

独立的生产技术包编辑和二次确认停止新增使用。新的生产准备状态由以下事实自动计算：

```text
订单已确认
+ 图纸已终审
+ BOM已发布
+ 执行工作包已生成
= 生产准备完成
```

历史生产技术包保留只读查询，不参与新订单状态计算。需要修改已发布技术内容时，通过BOM新版本和生产变更记录完成，不覆盖原版本。

## 5. 五阶段生产进程

### 5.1 生产准备

显示订单、终审图纸、BOM版本、BOM校验、下料清单和工作包生成状态。

订单确认完成后，或用户首次进入生产准备阶段时，系统幂等创建一份BOM草稿：已有草稿时继续编辑原草稿，不重复新建；终审图纸版本变化时只提示差异和创建新版本，不覆盖已发布BOM。

主要操作只有一个，按照缺失条件动态显示：

- 前往图纸终审
- 生成BOM
- 编辑并核验BOM
- 发布BOM
- 查看生产准备结果

### 5.2 物料齐套

显示总物料项、已齐套项、缺料项、采购在途项、待领料项和已领料项。

系统从统一库存和采购事件计算状态。用户可以从该阶段快捷进入采购或库存页面，但不能在履约中心生成第二套采购单、到货记录或库存流水。

采购默认服务全厂公共库存，不强制绑定单个TM订单。生产门樘只记录库存预留、需求覆盖和实际领料关系。

### 5.3 加工装配

实际下料、骨架、焊接、表面处理、装配等均作为执行工作包。工作包显示待开始、进行中、已完成和阻塞状态。

主界面优先显示当前可执行工作、下一工序和阻塞原因。允许增加临时工序或跳过不适用工序，但必须填写原因并形成事件记录。

### 5.4 质检入库

必要工作包未结束时不能提交成品质检。质检结果包括合格、不合格和让步接收。

不合格时自动进入返工状态，并创建或关联返工工作包；返工完成后重新质检。合格或授权让步接收后允许办理成品入库。生产页面只提供快捷操作，实际调用库存管理的统一成品入库接口，形成唯一库存流水，不在生产模块另存一份入库记录。

### 5.5 发货完成

系统读取TM订单实际收款，不在门樘页面重复登记收款。未收金额大于零时默认阻止发货；确需放行时必须填写原因和授权人，欠款继续保留。

发货阶段记录出库、物流或司机、车牌或运单、运输和签收状态。签收后门樘履约完成。

## 6. 页面结构

### 6.1 生产管理入口

生产管理页面由三部分组成：

1. 订单和门樘筛选区。
2. 当前门樘摘要区。
3. 五阶段生产进程区。

门樘摘要固定显示生产编号、客户、产品、尺寸、交期、当前阶段、阻塞状态和当前有效版本。

左侧导航仅保留一个“生产管理”入口。BOM与工艺准备、采购、库存等明细通过阶段卡片进入原有业务页面，并提供明确的返回生产进程入口，避免再次形成多个并列的生产主流程。

### 6.2 阶段卡片

每个阶段使用统一结构：

- 阶段名称和状态。
- 已完成结果摘要。
- 未满足条件或阻塞原因。
- 唯一主要操作。
- 查看详细资料的次要入口。

系统默认展开当前阶段。已完成阶段折叠为摘要，未来阶段显示进入条件，不提前展示无效表单。

### 6.3 异常和记录

异常不再作为独立生产阶段。未解决异常显示在页面顶部，并同时附着在发生问题的阶段。异常处理使用当前视口居中的弹窗或侧边抽屉。

时间线改为“全部记录”抽屉，统一显示BOM发布、库存、采购、工作包、质检、入库、发货、异常和授权事件。

## 7. 状态计算

当前阶段由真实业务事件自动计算，不允许手工选择总进度：

1. 生产准备条件未完成时，阶段为生产准备。
2. 生产准备完成但必要物料未满足时，阶段为物料齐套。
3. 必要物料满足且存在未完成工作包时，阶段为加工装配。
4. 工作包完成但质检或成品入库未完成时，阶段为质检入库。
5. 成品已入库但尚未签收时，阶段为发货完成。
6. 已签收时，门樘状态为履约完成。

总进度百分比仅作为辅助信息，由已完成阶段和工作包权重计算，不能作为阶段切换依据。

物料未完全齐套时允许开展不依赖缺失物料的工作包。系统必须明确显示哪些工作可执行、哪些工作因缺料或前置工序被阻塞。

## 8. 单账号试运行

第一阶段所有页面和操作对当前测试账号开放，不增加人员选择和权限阻断。

试运行订单增加“试运行”标记，默认不进入正式经营统计。用户可以复制订单形成新的测试记录，但不能重置或覆盖已有库存流水和业务事件。

试运行重点观察：

- 是否存在同一数据需要录入两次。
- 阶段判断是否符合现场实际。
- 系统提示的下一步是否准确。
- 自动生成内容是否允许必要的人工调整。
- 阻塞原因是否足以指导处理。
- 返回、刷新和重复点击是否产生重复记录。

## 9. 错误与幂等处理

- 每个阶段必须返回可理解的阻塞原因，不能只显示“操作失败”。
- BOM生成、BOM发布、门樘创建、需求生成和工作包生成必须保持幂等。
- 网络中断后刷新页面必须从后端事实恢复，不依赖浏览器内临时状态。
- 已发布BOM不能直接覆盖；修改必须创建新版本。
- 已确认库存流水不能删除或覆盖，只能用相反业务流水冲销。
- 未完成前置条件时，按钮保持禁用并显示具体缺失项。

## 10. 迁移与实施策略

第一轮不重写底层订单、BOM、库存、采购和履约数据库，只建设统一的五阶段流程层，并关闭重复写入口。

实施顺序：

1. 新建五阶段生产进程和自动状态计算。
2. 将现有BOM、库存、采购、工作包、质检和发货数据接入阶段摘要。
3. 停用新订单的生产技术包编辑和二次确认。
4. 将实际下料统一为生产工作包。
5. 停用履约中心内重复的采购、库存和门樘收款录入。
6. 保留旧数据的只读查看入口。
7. 使用试运行订单完成全流程验证。
8. 根据试运行结果再删除不再需要的旧组件。

## 11. 验收标准

- 新用户无需理解模块名称，也能根据“下一步”完成一樘门的完整履约。
- BOM只有一个发布入口，实际下料只有一个完成入口。
- 采购、库存和收款只有各自的唯一事实来源。
- 主页面不再出现七个并列业务页签。
- 当前阶段、阻塞原因和下一步操作与后端事实一致。
- 一张试运行订单可完成“订单确认、BOM发布、物料准备、生产执行、质检入库、发货签收”。
- 重复点击和刷新不会产生重复门樘、BOM、需求、工作包或库存流水。
- 所有关键操作都能通过生产编号和TM订单号追溯。

## 12. 暂不纳入

- 岗位工作台和正式权限矩阵。
- 自动排产和产能优化。
- 复杂设备数据采集。
- 门框具体下料规则深化。
- 3D下料预览。
- 删除历史生产技术包和旧履约数据。
