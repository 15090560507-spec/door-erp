# 分层 BOM、生产工序与人员工资一体化设计

日期：2026-09-14  
状态：已确认设计，待实施  
适用项目：西州将军 Door ERP

## 1. 背景

当前系统已经具备订单确认、BOM 草稿与发布、物料需求、工作包、质检、入库、发货和计件工资草稿等基础能力，但在实际试用中出现以下问题：

1. 左侧仍存在独立的“BOM与下料”，与“生产管理”的生产准备阶段并列，用户需要在两个入口之间往返。
2. 门框总成、门扇面板和门扇骨架被同时当成生产对象和库存物料，导致按图定制件出现无意义的“待匹配”。
3. 门框没有明确拆分为门框外皮和门框骨架，难以分别管理材料、工序和成本。
4. 生产页面同时显示顶部状态指标、五阶段统计和门樘五阶段进度，重复表达同一事实。
5. 加工装配采用按状态分栏的看板。订单较少时会出现大量空框；订单较多时又难以从部件角度连续查看材料和工序。
6. 工艺路线写死在工作包生成逻辑中，缺少标准模板和单门调整入口。
7. 拼装负责人、协作人员、拼装工位和交付质检之间没有统一记录。
8. 人员、计件、考勤和月度工资尚未形成完整闭环。

本设计将 BOM、生产工序、拼装责任和工资核算统一到同一条门樘履约链中，同时保留采购、库存、质检和财务各自唯一的业务台账。

## 2. 目标

- “生产管理”成为生产履约唯一主入口。
- 门框和门扇采用父子分层 BOM，明确总成、外皮、骨架和真实原材料。
- 按图自制件不要求匹配基础物料，只有会采购、入库和领料的真实物料需要匹配。
- 加工装配按 BOM 部件行展示，物料状态与生产工序状态分离。
- 工艺路线可集中维护，也可对当前门樘进行有留痕的调整。
- 每樘门可以分配主拼装人、协作人员、工位和计划日期。
- 工序完成、质量确认、计件形成和月度工资结算可以追溯到同一个生产编号和 TM 订单号。
- 当前测试阶段不限制角色，由一个账号走通全部流程。

## 3. 非目标

- 本轮不完善门框 CAD 下料算法和端部异形规则。
- 不为每一种定制尺寸创建一条基础商品或库存物料。
- 不建设完整财务总账、银行代发、社保申报或税务申报系统。
- 个税和社保暂时作为可录入、可导入的代扣项，不自动套用随法规变化的计算公式。
- 不删除历史业务数据，不物理覆盖已发布 BOM、已结算工资和已发生库存流水。

## 4. 统一业务边界

| 业务事实 | 唯一可写入口 | 生产管理中的表现 |
|---|---|---|
| 订单与门樘参数 | 订单确认 | 只读摘要和变更提醒 |
| BOM、下料清单、工艺路线 | 生产准备 | 直接编辑、核验和发布 |
| 采购单与供应商到货 | 采购管理 | 显示缺口、采购中和预计到货 |
| 库存、预留、领退料 | 库存管理 | 显示齐套、预留和领料状态 |
| 部件加工与拼装 | 生产管理 | 更新工序、负责人和完成情况 |
| 过程检验与成品质检 | 生产管理的质检环节 | 显示结论、返工和放行记录 |
| 成品入库 | 库存管理的成品流水 | 在质检阶段调用同一入库接口 |
| 收款 | 订单确认 | 发货阶段读取已收和未收金额 |
| 发货与签收 | 生产管理 | 办理出库、运输和签收 |
| 人员与工资 | 人员工资 | 生产页显示人员和计件结果 |

## 5. 分层 BOM 模型

### 5.1 标准结构

```text
门樘
├─ 门框总成（按图自制）
│  ├─ 门框外皮（按图自制）
│  │  └─ 原板/卷料（库存或采购物料）
│  └─ 门框骨架（按图自制）
│     └─ 骨架型材（库存或采购物料）
├─ 门扇总成（按图自制）
│  ├─ 门扇外皮（按图自制）
│  │  └─ 原板/卷料（库存或采购物料）
│  └─ 门扇骨架（按图自制）
│     └─ 骨架型材（库存或采购物料）
├─ 门套/门头/门柱（按图自制或外购）
├─ 玻璃与线条
├─ 锁具、拉手、合页和开启机构
└─ 花件、辅料及其他配件
```

对开门、子母门、四开门和两定两开门可以在门扇总成下继续按实际门扇实例拆分，但公共材料允许汇总形成采购或领料需求。

### 5.2 部件类型

每条 BOM 行新增或明确以下字段：

- `parent_component_id`：父级 BOM 行。
- `item_kind`：`assembly`、`manufactured_part`、`material`、`purchased_part`、`service`。
- `procurement_mode`：`make`、`buy`、`stock`、`outsource`。
- `operation_code`：部件对应的工艺分类。
- `material_id`：只有真实库存或采购物料才必需。
- `drawing_parameter_json`：按图生产所需的尺寸、款式、颜色和来源字段快照。

### 5.3 匹配规则

- `assembly` 和 `manufactured_part` 使用 `procurement_mode=make`，不进入物料匹配，界面显示“按图自制”。
- `material`、`purchased_part` 使用 `stock` 或 `buy` 时必须匹配基础资料中的物料档案。
- `service` 和 `outsource` 匹配外协服务或供应商服务项目，不占用库存。
- 基础资料只维护通用物料，例如 0.8 mm 304 不锈钢板、骨架型材、锁体和油漆，不维护“900×2100 门框骨架”之类的定制尺寸。
- 定制尺寸、展开尺寸、数量和损耗属于 BOM 需求属性，不属于物料主数据属性。

为了兼容旧数据，数据库中原有 `match_status=无需物料` 可以继续保存，但自制件在界面统一显示“按图自制”，不显示“未匹配”或“待匹配”。

## 6. 工艺路线

### 6.1 标准工艺路线

在“基础资料”增加“工艺路线”子页面，按部件类型维护标准模板：

- 模板名称、适用产品、适用部件和启用状态。
- 工序名称、工序编码、排序号和前置工序。
- 是否需要过程检验。
- 标准工时、计件单位和默认计件单价。
- 默认岗位、班组或工位。
- 可增加、删除、启停和拖动排序。

建议默认模板：

| 部件 | 默认工序 |
|---|---|
| 门扇外皮 | 领料 → 下料 → 折弯 → 焊接 → 打磨 → 表面处理 → 完成 |
| 门扇骨架 | 领料 → 下料 → 焊接 → 防锈 → 完成 |
| 门框外皮 | 领料 → 下料 → 折弯 → 焊接 → 打磨 → 表面处理 → 完成 |
| 门框骨架 | 领料 → 下料 → 焊接 → 完成 |
| 五金配件 | 齐套 → 安装 |
| 门樘总成 | 部件齐套 → 拼装 → 调试 → 提交成品质检 |

### 6.2 门樘工艺快照

BOM发布时，把当时的标准工艺路线复制为门樘工艺快照。以后修改标准模板，不影响已经发布或正在生产的门樘。

在生产管理提供“本单工序调整”：

- 新增、删除、启停和排序当前门樘的工序。
- 修改前置关系、是否质检、执行人、标准工时和计件单价。
- 修改必须填写原因并形成事件记录。
- 已完成或已生成工资记录的工序不能物理删除，只能停用或通过冲减处理。

## 7. 生产执行模型

### 7.1 物料状态和工序状态分离

物料状态用于回答“东西是否具备”：

- 无需物料
- 库存可用
- 已预留
- 库存不足
- 采购中
- 部分到货
- 已到货
- 已领料

工序状态用于回答“加工到哪里”：

- 待前序
- 待开始
- 可执行
- 进行中
- 待过程质检
- 已完成
- 暂停
- 异常
- 返工
- 已跳过

采购中不能作为加工状态；下料中、折弯中、油漆中也不能作为库存状态。

### 7.2 BOM式工序表

“加工装配”删除按状态分成八个空框的看板，改为分层 BOM 工序表：

| 部件 | 物料状态 | 工序进度 | 当前工序 | 负责人 | 计划/实际 | 操作 |
|---|---|---|---|---|---|---|

交互规则：

- 默认按门框、门扇、门套、玻璃和五金分组。
- 父级总成可展开查看子件、原材料、领料和工序记录。
- 工序进度使用紧凑的横向步骤条，点击当前工序打开更新窗口。
- 支持多选 BOM 行，批量分配负责人、开始、提交质检或确认完成。
- 暂停、异常和返工显示在对应部件行，不再独立占空白栏目。
- 被物料或前序工序阻塞时显示具体原因和对应处理入口。
- 配件只显示适用的简单路线，不强制经过板材加工工序。

## 8. 拼装分配

拼装是“门樘总成”的正式工序，不建立第二套平行任务。

每樘门记录：

- 主拼装人。
- 协作人员，可多选。
- 拼装工位。
- 计划开始和计划完成日期。
- 实际开始和完成时间。
- 门樘数量和实例编号。
- 拼装说明、异常和返工记录。

必要部件未完成或关键配件未齐套时，拼装状态为阻塞。特殊情况下允许提前开始，但必须填写放行原因。拼装完成后自动进入成品质检，并可从质检记录追溯主拼装人和协作人员。

## 9. 生产管理页面

### 9.1 导航

经营管理保留：

- 订单确认
- 生产管理
- 采购管理
- 库存管理
- 基础资料
- 人员工资

删除左侧独立的“BOM与下料”。原 `/cutting` 路由作为兼容入口保留，但不再出现在主导航；生产准备内容优先直接嵌入生产管理。

### 9.2 全局层

页面顶部只保留四个不重复的管理指标：

- 在制门樘
- 交期风险
- 物料缺口
- 异常待处理

五阶段改为订单列表的筛选标签，不再单独占一整排统计卡。订单列表显示客户、TM订单号、生产编号、产品、尺寸、交期、当前阶段和阻塞原因。

### 9.3 门樘层

选择门樘后依次显示：

1. 门樘摘要：TM订单号、生产编号、客户、尺寸、交期、BOM版本、拼装负责人。
2. 唯一一条五阶段进度条：生产准备、物料齐套、加工装配、质检入库、发货完成。
3. 当前阶段工作区。
4. 异常入口和全部记录入口。

生产准备阶段直接完成 BOM 生成、人工增删、物料核验、工艺调整和发布。已发布 BOM 通过新版本修改，不覆盖历史版本。

## 10. 人员档案

在“基础资料”增加“人员与计件基础”，人员工资页面负责工资业务。

员工档案包括：

- 员工编号、姓名、手机号、班组、岗位和在职状态。
- 可执行工序、默认工位和默认班组。
- 工资类型：固定工资、计件工资、固定加计件。
- 入职日期、离职日期和备注。

工资敏感字段与生产基础字段分开保存。当前测试阶段不限制角色，但数据结构预留后续工资查看权限。

## 11. 计件和工资核算

### 11.1 计件来源

工序完成并通过必要质检后，系统按合格数量自动形成计件草稿：

```text
计件金额 = 合格数量 × 工序计件单价
```

每条计件记录必须关联：

- 员工
- TM订单号
- 生产编号
- BOM版本
- 部件与工序
- 工作步骤记录
- 合格数量、单价和金额

同一个完成记录只能生成一次计件草稿。工序撤销、返工或数量更正时，不删除已审核数据，而是生成冲减或补差记录。

### 11.2 月度工资

```text
月度应发 = 基本工资折算 + 已审核计件 + 加班 + 补贴 + 奖金 - 请假扣款 - 其他扣款
实发工资 = 月度应发 - 社保 - 个税 - 其他代扣
```

人员工资模块包含：

- 工资方案：基本工资、计件规则和标准工作日。
- 考勤数据：出勤、请假、加班，支持手工录入和 Excel 导入。
- 调整项：补贴、奖金、扣款、补差和冲减。
- 月度工资表：计算、复核、审核、锁定和导出。
- 员工工资明细：固定工资、计件来源、调整项和代扣项。

工资状态：`草稿 → 待复核 → 已审核 → 已锁定`。锁定后的月份不能直接修改，必须通过下一期补差或授权解锁并留下审计记录。

## 12. 数据表调整

优先扩展现有履约数据库，避免平行建立第二套生产数据。

建议新增或扩展：

- `fulfillment_components`：父级、部件类型、取得方式、按图参数。
- `process_route_templates`：工艺路线模板。
- `process_route_template_steps`：模板工序。
- `door_process_steps`：门樘工艺快照和实际状态。
- `production_assignments`：主负责人、协作人员和工位。
- `employees`：员工生产档案。
- `salary_schemes`：工资方案。
- `piecework_entries`：计件明细和冲减记录。
- `attendance_entries`：考勤及加班数据。
- `payroll_adjustments`：奖金、补贴、扣款和补差。
- `payroll_periods`：工资月份及锁定状态。
- `payroll_items`：员工月度工资结果。

所有业务表保留 `created_at`、`updated_at`、操作人和来源记录。关键生成操作增加唯一约束或幂等键。

## 13. 状态推进

门樘五阶段仍作为统一进程：

1. **生产准备**：BOM已生成、缺项已处理、工艺路线已确认并发布。
2. **物料齐套**：关键物料可用；非关键缺料允许形成清晰阻塞或局部生产条件。
3. **加工装配**：部件加工、配件安装、拼装和调试按工艺路线推进。
4. **质检入库**：拼装完成、成品质检合格并完成成品入库。
5. **发货完成**：满足收款或授权放行条件，完成出库、运输和签收。

当前阶段由后端事实计算，前端不自行拼接状态。异常不作为阶段，而是附着在具体 BOM 行、工序、质检或发货记录上。

## 14. 迁移策略

- 原 `FRAME_ASSEMBLY` 迁移或映射为门框总成父级。
- 新 BOM 生成 `FRAME_SKIN` 和 `FRAME_SKELETON` 两个自制子件。
- 原 `PANEL` 映射为门扇外皮，原 `SKELETON` 映射为门扇骨架。
- 自制件的旧“无需物料”在界面显示为“按图自制”。
- 已发布 BOM 保持只读；需要使用新结构时创建新版本。
- 历史工作包继续可查，新 BOM 使用门樘工艺快照；两种数据在时间线中统一展示。
- 已形成的工资草稿、库存流水、采购关联和质检记录不得物理删除。

## 15. 错误处理与审计

- BOM发布前逐项校验真实物料匹配、计划数量和工艺路线。
- 自制件不会因没有 `material_id` 阻塞发布。
- 缺料时必须指出具体物料、缺口和受影响工序。
- 工序更新使用版本或更新时间校验，避免多人覆盖。
- 发布、领料、完成工序、质检、入库、计件和工资锁定均防止重复提交。
- 单门工艺调整、跳过工序、提前拼装、返工、欠款发货和工资更正必须记录原因。
- 所有关键事件通过 TM订单号、生产编号、BOM版本和员工编号追溯。

## 16. 实施顺序

### 阶段一：入口和界面收拢

- 删除主导航中的“BOM与下料”。
- 将 BOM 工作台嵌入生产准备阶段。
- 合并重复指标和阶段展示。
- 将加工装配改为 BOM 式工序表。

### 阶段二：分层 BOM 与工艺路线

- 增加 BOM 父子层级和部件类型。
- 自动生成门框外皮、门框骨架、门扇外皮和门扇骨架。
- 修正自制件匹配规则。
- 建立工艺路线模板、门樘快照和本单调整。

### 阶段三：拼装和人员

- 建立员工档案。
- 增加工序执行人、协作人和拼装分配。
- 完成拼装到成品质检的状态联动。

### 阶段四：工资闭环

- 自动形成计件草稿。
- 建立考勤、调整项和工资方案。
- 完成月度工资计算、复核、审核、锁定和导出。

### 阶段五：迁移和验收

- 迁移或兼容旧 BOM 与工作包。
- 完成后端单元测试、接口回归和前端生产构建。
- 使用试运行订单完成整单流程验证。

## 17. 验收标准

1. 左侧只有一个生产管理入口，BOM可在门樘生产准备阶段完成。
2. 页面不再三次重复展示阶段信息。
3. 门框和门扇均明确拆分外皮与骨架。
4. 按图自制件不出现待匹配，真实物料仍必须匹配基础资料。
5. 加工装配能够从一张表看见部件、物料、工序、负责人和异常。
6. 标准工艺路线可以独立调整，当前门樘可以有留痕地覆盖。
