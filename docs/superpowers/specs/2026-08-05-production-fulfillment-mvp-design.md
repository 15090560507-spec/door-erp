# 简版生产履约系统设计

日期：2026-08-05

## 1. 目标

在现有门业 ERP 中增加一套简单、完整、可逐步扩展的生产履约流程：

`销售下达 → 手工 BOM → 采购/领料 → 综合下料 → 排单生产 → 成品质检 → 成品入库 → 发货`

现有图纸信息录入、图纸绘制、图纸初审、图纸终审、效果渲染和报价系统统一归入“订单前期”。新增功能归入“生产履约”。两个业务域只在销售点击“下达生产订单”时衔接。

首版优先保证流程可用、数据可追溯和现有功能不受影响，不一次加入复杂制造管理能力。

## 2. 已确认原则

- 一张生产订单只包含一樘门。
- 图纸终审通过后，销售可以点击“下达生产订单”。
- “下达生产订单”是订单前期进入生产履约的唯一节点。
- 报价单不是下达生产的必填条件；存在报价时保存报价快照。
- 同一终审图纸默认只能直接下达一次；再次生产应复制生产订单并生成新单号。
- 下料开始前允许销售申请撤回；下料开始后只能走生产变更，不直接修改原订单。
- BOM 首版由技术人员手工填写，不自动生成。
- 每张生产订单只生成一张综合下料单。
- 生产采用固定工序模板，并允许跳过不适用工序。
- 首版只做成品质检，不做过程质检。
- 质检合格后必须先入库；立即发货时执行连续的“快速入库 + 出库”。
- 一张发货单可以合并多个生产订单；首版不允许一樘门拆分多次发货。
- 用户从单一角色升级为可以拥有多个业务权限。

## 3. 架构与隔离边界

采用“现有整体项目内的独立生产模块”方案，不建立第二套部署服务，也不把生产状态塞进现有图纸任务状态机。

### 3.1 订单前期

继续由现有任务、CAD、效果渲染和报价模块负责：

- 图纸信息录入
- 图纸绘制
- 图纸初审
- 图纸终审
- 效果渲染
- 报价系统

现有路由、数据格式、CAD 绘图算法、报价计算和效果渲染请求协议不因生产模块改变。

### 3.2 生产履约

新增独立模块负责：

- 生产订单
- 手工 BOM
- 生产物料库
- 简单采购与库存流水
- 综合下料单
- 排单与固定工序
- 成品质检
- 成品入库与发货
- 生产总览

### 3.3 唯一衔接方式

销售下达生产时，系统读取已经终审通过的图纸任务，创建不可变的生产来源快照。生产模块后续只读取快照，不反向修改原任务、原图纸或原报价。

快照至少包含：

- 来源任务 ID 和终审版本
- 完整图纸表单数据
- 终审意见和终审人
- 使用终审参数生成并固化的最终 DXF 副本
- 正面、反面预览图
- 客户参考图片
- 客户、项目和订货信息
- 存在时的报价单及明细
- 下达人、下达时间和文件校验值

## 4. 持久化方案

生产模块使用独立的 `data/production.db` SQLite 数据库，并将生产快照文件保存到 `data/production_files/`。两者都位于现有 Docker 数据卷中。

选择 SQLite 的原因：

- 不增加外部数据库部署成本。
- 支持事务和关联关系，适合订单、BOM、库存流水和发货单。
- 与现有 JSON 任务、用户和报价文件隔离。
- 后续迁移 PostgreSQL 时可以通过生产仓储层替换，不要求改页面协议。

生产模块不得直接写入现有 `tasks_database.json`、`quotes_database.json` 或 CAD 模板。

## 5. 生产订单

### 5.1 下达条件

- 来源图纸状态为“已通过”。
- 客户或订货单位存在。
- 门型、尺寸、开向、材质、正反面款式等关键图纸字段完整。
- 终审参数能够通过现有 CAD 生成逻辑成功生成 DXF，或已有 DXF 文件可读取。
- 当前终审版本尚未直接下达过生产。

### 5.2 下达确认

销售确认以下信息：

- 客户或订货单位
- 项目名称，可为空
- 要求交期
- 销售备注
- 是否带入现有报价快照

首版数量固定为一樘。生产单号格式为 `SCYYYYMMDDNNN`，例如 `SC20260805001`。

### 5.3 订单操作

- 查看来源和冻结快照
- 复制生产订单
- 下料前申请撤回
- 下料后发起生产变更
- 暂停、恢复和作废
- 查看完整操作记录

复制订单只复制基础配置与快照，不复制 BOM 执行记录、采购、领料、下料、工序、质检、库存和发货记录。

## 6. 手工 BOM 与生产物料库

### 6.1 手工 BOM

生产订单创建后生成空白 BOM 草稿。技术人员手工填写：

- 分类
- 物料名称
- 规格
- 材质
- 厚度
- 数量
- 单位
- 自制或外购
- 备注

BOM 状态保持简单：`草稿 → 已发布`。草稿可编辑；发布后才允许进入采购、领料和综合下料。首版不实现自动生成、版本差异、自动补料或自动退料。

### 6.2 生产物料库

生产物料库独立于报价配件库，避免仓储和采购资料变更影响报价。

字段包括：

- 物料编码
- 名称
- 分类
- 材质、规格、厚度
- 库存单位
- 默认供应商
- 默认仓位
- 是否启用
- 备注

BOM 允许选择正式物料，也允许录入一次性临时物料。首版不做复杂单位换算、安全库存和供应商价格历史。

## 7. 简单采购与库存

首版提供足够完成流程的基础能力：

- 手工创建采购单
- 登记采购到货和材料入库
- 登记生产领料、生产退料、盘点调整和报废
- 查看当前库存与库存流水
- 在生产订单上手工标记缺料状态

采购状态：`草稿 → 已下单 → 部分到货 → 已完成`。

库存数量由流水汇总，不允许直接覆盖总数。首版不做库存自动预占、自动缺料计算、采购自动合并、复杂批次分配和采购审核流。

## 8. 综合下料单与排单

### 8.1 综合下料单

已发布 BOM 可以生成一张综合下料单，按类别显示所有明细。每条记录包含：

- 物料名称、规格和数量
- 下料人
- 完成状态
- 实际数量
- 备注

综合下料单状态：`草稿 → 已下发 → 下料中 → 已完成`。

首版支持页面查看、打印和 Excel/PDF 导出。BOM 发布后如需修改，由负责人先撤回 BOM；若已经开始下料，则通过生产变更备注人工处理，首版不自动生成差异单据。

### 8.2 排单

排单仅记录：

- 计划开始日期
- 计划完成日期
- 生产人
- 缺料状态
- 负责人

生产订单下达后可以预排；BOM 发布且综合下料单已下发后可以正式开始生产。

## 9. 生产进度

固定工序模板为：

`下料 → 激光/冲孔 → 折弯 → 焊接组装 → 表面处理 → 装配 → 包装`

每道工序状态为：`待开始 / 进行中 / 已完成 / 不适用`。

每道工序记录生产人、开始时间、完成时间和备注。默认按顺序推进；首版不做并行审批、班组产能、工时报工和复杂返工成本。

全部必要工序完成后，生产订单进入待成品质检。

## 10. 成品质检、入库与发货

### 10.1 成品质检

质检记录包含：

- 结果：合格或不合格
- 质检人和时间
- 退回工序
- 照片
- 备注

不合格时退回选定工序；该工序重新完成后再次质检。首版不做过程质检和让步接收审批。

### 10.2 成品入库

质检合格后必须办理成品入库，记录成品编号、仓位、操作人和时间。立即发货时，快速入库出库仍生成独立的入库和出库流水。

### 10.3 发货

一张发货单允许关联多个生产订单，记录：

- 客户和项目
- 收货地址、联系人和电话
- 物流方式
- 车牌或运单号
- 发货时间和照片
- 签收状态与异常备注

发货状态：`待发货 → 已出库 → 运输中 → 已签收 → 已完成`。

首版不支持一樘门拆分多次发货。

## 11. 状态模型

生产订单主阶段为：

`BOM准备 → 备料 → 下料 → 生产 → 质检 → 入库 → 发货 → 完成`

暂停、撤回和作废作为独立状态标记，不覆盖关联单据历史。

缺料状态单独保存为：`未知 / 不缺料 / 缺料`。当前工序单独保存，不把所有子状态塞进生产订单主状态。

## 12. 页面结构

### 12.1 导航分组

订单前期保留现有页面；新增“生产履约”入口。首版生产履约包含：

- 生产总览
- 生产订单
- 生产物料
- 采购与库存
- 综合下料与排单
- 生产进度
- 成品质检
- 成品与发货

登录后的默认页面仍为图纸信息录入。

### 12.2 生产订单详情

订单详情用页签承载：

- 基本信息与图纸快照
- BOM
- 采购与库存
- 综合下料与排单
- 生产进度
- 质检
- 入库与发货
- 操作记录

### 12.3 生产总览

提供可点击筛选的卡片：

- BOM 待填写
- 缺料
- 待下料
- 生产中
- 待质检
- 待入库
- 待发货
- 已完成

## 13. 权限

保留现有 `role` 字段用于兼容，并为用户增加 `permissions` 数组。现有账号没有权限数组时，后端按原角色映射默认权限。

首版业务权限：

- `production.sales`：下达、复制和申请撤回生产订单
- `production.technical`：填写及发布 BOM
- `production.purchase`：采购管理
- `production.warehouse`：材料和成品出入库
- `production.schedule`：排单
- `production.cutting`：综合下料
- `production.worker`：更新生产工序
- `production.quality`：成品质检
- `production.shipping`：发货与签收
- `production.manager`：撤回审批、生产变更、暂停和恢复
- 超级管理员拥有全部权限

权限必须同时在前端按钮和后端接口检查。一个用户可以拥有多个生产权限。

## 14. 后端接口边界

生产接口统一放在 `/api/production` 下，首版分组如下：

- `/orders`：生产订单、下达、复制、撤回和状态
- `/materials`：生产物料库
- `/orders/{id}/bom`：手工 BOM
- `/purchases`：采购及到货
- `/inventory`：库存与流水
- `/orders/{id}/cutting-sheet`：综合下料单
- `/orders/{id}/schedule`：排单
- `/orders/{id}/operations`：固定工序
- `/orders/{id}/quality`：成品质检
- `/finished-goods`：成品入库与出库
- `/shipments`：发货与签收
- `/dashboard`：生产总览统计

所有接口要求登录，并按业务权限执行后端校验。

## 15. 错误处理与审计

- 业务校验失败返回明确中文原因，不返回笼统的 500。
- 重复下达、未发布 BOM 就下料、未质检入库等冲突返回 409。
- 无权限返回 403，未登录返回 401。
- 关键操作写入独立审计记录：操作人、时间、动作、对象、原因和变更摘要。
- 作废采用状态标记，不物理删除有关联流水的业务记录。

## 16. 验证范围

### 16.1 后端自动测试

- 未登录不能访问生产接口。
- 多权限用户可以访问被授予的模块，不能访问未授权模块。
- 只有终审通过的图纸可以下达生产。
- 同一终审版本不能重复直接下达。
- 报价不存在时仍可下达生产。
- 下料开始前可以撤回，下料开始后拒绝直接撤回。
- BOM 未发布时不能生成正式综合下料单。
- 工序完成后可进入质检；质检不合格可退回工序。
- 质检未通过不能入库；未入库不能发货。
- 一张发货单可以关联多个已入库生产订单。

### 16.2 前端验证

- 订单前期现有页面和流程保持可用。
- 下达生产有明确成功或失败反馈。
- 生产总览卡片可以筛选列表。
- 页面和按钮按权限正确显示。
- 生产订单从下达到签收可以完整走通。
- 云端 Docker 重建后生产数据和快照文件仍然存在。

## 17. 首版明确暂缓

- BOM 自动生成和计算规则
- 激光展开、开槽图、折弯图和加工级 BOM
- 多樘门生产订单
- 自动库存预占和自动缺料计算
- 复杂采购审核、合并采购和供应商价格历史
- 复杂批次、条码和扫码
- 过程质检
- 工时、计件工资和产能排程
- 自动补料、退料差异单
- 单樘门拆分发货
- 独立微服务或外部数据库部署

以上能力后续可以围绕生产订单和手工 BOM 扩展，不要求修改订单前期业务。
