# Door ERP 门樘履约中心设计

## 1. 文档状态

- 设计日期：2026-08-13
- 状态：设计定稿，待实施计划审核
- 适用项目：Door ERP
- 设计对象：替代旧生产履约模块和 ERPNext 桥接方案的新生产管理系统

## 2. 决策摘要

Door ERP 不再以 ERPNext 为生产履约系统，也不照搬传统 ERP 的固定单据链。新系统采用“门樘履约中心式”架构：

- 一个客户订单可以包含多樘门。
- 每樘门生成独立生产编号，是生产、用料、成本、工资、质量、库存、发货和售后的最小追踪对象。
- 每樘门由一名整单负责人协调，下料、焊接、表面处理等实际工作由不同执行人员完成。
- 下料人员编制并确认生产技术包后，满足条件的备料和生产工作立即释放，不设置第二次技术审批。
- 生产技术包不是简单 BOM，而是产品快照、构件树、材料需求、图纸文件、工艺路线和工作包网络的完整集合。
- 工作包类型和路线可配置，不把花件、玻璃、精雕、蚀刻等业务写死在代码中。
- 采购和外协需求归属于具体门樘，允许跨门樘合并办理，收货和成本仍能拆回来源门樘。
- 所有采购件、定制件和外协回厂件先经仓库登记；按检验策略完成来料检验后才能进入可用库存。
- 仓库按领料清单逐项确认实发数量，确认后直接扣减库存，不要求领料人二次确认。
- 执行人提交实际工作完成；整单负责人处理异常、返工组织和最终完工。
- 独立质检人员负责来料检验和成品质检，整单负责人无权自行判定合格。
- 成品质检合格后必须办理成品入库，再由发货人员协调销售、财务和仓库完成发货。
- 发货必须满足订单收款节点；特殊情况可授权放行，但欠款事实和授权记录必须保留。
- 工资第一版支持固定工资和可配置计件工资，不建设复杂薪税系统。
- 生产技术包确认后禁止覆盖原参数和图纸，任何生产变化必须通过生产变更单生成新版本。

## 3. 第一性目标

系统必须让每一樘门在任何时刻都能回答：

1. 客户最终确认的生产内容是什么，当前执行哪个版本？
2. 谁对整单交期负责，谁正在执行具体工作？
3. 哪些材料、配件、外协件已经具备，哪些仍缺失？
4. 当前可以开展哪些工作，哪些节点因何受阻？
5. 实际完成到哪里，预计是否能按期完成？
6. 来料和成品是否合格，返工是否完成并复检？
7. 实际领用了什么、花了多少钱、形成多少工资？
8. 成品在哪里，是否满足收款和发货条件？
9. 谁在何时修改、确认、取消或授权了关键业务？

系统优化目标按优先级排序：

1. 生产内容和图纸版本准确。
2. 工作、物料、外协和异常透明。
3. 允许多条准备路线并行和局部开工。
4. 责任清晰且现场录入足够简单。
5. 库存、成本、质量和工资可追溯。
6. 逐步沉淀模板和经营数据。

## 4. 系统边界

### 4.1 继续保留的 Door ERP 能力

- 图纸信息录入
- CAD 绘制、预览和导出
- 图纸初审、终审及修改闭环
- 报价、Excel/JPG/PDF 导出
- 用户、权限和基础配置
- 销售确认及生产订单下达入口

### 4.2 新建能力

- 客户订单与多门樘生产单
- 生产技术包与版本管理
- 构件树、工作包和工艺路线模板
- 供应需求、采购、定制采购和外协
- 原料、配件、在制品和成品仓储
- 来料检验、过程检验、成品质检和返工
- 整单协调、执行任务、局部开工和异常中心
- 应收、收款节点、发货放行、应付和付款登记
- 门樘成本、固定工资和计件工资
- 成品入库、发货、运输跟踪和签收
- 岗位工作台、通知、审计和基础统计

### 4.3 明确不做

- 不继续依赖 ERPNext 运行生产业务。
- 不复制 ERPNext 源代码或数据库结构。
- 不沿用旧生产模块的状态和库存作为新系统事实数据。
- 第一版不做完整会计总账、科目、税务、资产和法定报表。
- 第一版不做自动智能排产、复杂产能优化和高级预测。
- 第一版不自动从 CAD 或图片生成生产技术包。
- 第一版不集成专用扫码枪、电子秤等硬件。
- 第一版不建设客户门户和供应商门户。

## 5. 现有系统迁移策略

### 5.1 旧生产模块

- 从顶部导航和业务入口停用。
- 旧数据保持只读留档，不迁入新系统，不参与新库存、采购、成本和进度计算。
- 新系统稳定验收前不删除旧数据库和文件。
- 新系统不得调用旧生产模块的写接口。

### 5.2 ERPNext 桥接

- 新系统不调用 ERPNext API，不再创建 ERPNext 销售订单。
- ERPNext 容器与数据先停止业务使用并保留备份，确认新系统稳定后再决定下线。
- `erpnext_syncs` 等映射记录只保留历史审计用途。
- ERPNext API Key、Secret 和公网入口在确认停用后从生产环境撤销。

### 5.3 新旧隔离

- 新生产模块使用独立表前缀或独立数据库文件。
- 新单号、库存流水、成本流水、工资流水均从新系统开始。
- 旧模块的物料档案如需复用，只通过一次性导入和人工校验进入新基础资料，不直接共享可变表。

## 6. 核心业务层级

```text
客户订单
├── 门樘生产单 -01
│   ├── 生产技术包 V1 / V2 / V3
│   ├── 构件树
│   ├── 工作包网络
│   ├── 供应、库存和领料
│   ├── 质量与返工
│   ├── 实际成本和计件工资
│   └── 成品、发货和售后追溯
├── 门樘生产单 -02
└── 订单级公共工作包
```

### 6.1 客户订单

客户订单负责：

- 客户、项目、销售、合同金额和交期
- 多樘门清单
- 收款计划、已收款和欠款
- 分批交付计划
- 整单采购、费用和交付汇总

报价不是创建或下达生产订单的必填前置条件。客户订单可以关联零份、一份或多份报价记录；未关联报价时，销售仍可依据终审图纸和客户确认信息下达生产，但合同金额、收款节点和发货条件必须按实际业务单独维护。

### 6.2 门樘生产单

门樘生产单负责：

- 独立生产编号
- 产品、尺寸、材料、款式、颜色、开向和数量
- 下料负责人、整单负责人、质检和发货状态
- 当前有效技术包版本
- 工作包、材料、质量、成本、工资、成品和交付

示例编号：

```text
DD20260813001
├── DD20260813001-01
├── DD20260813001-02
└── DD20260813001-03
```

配置完全相同的门仍生成独立门樘生产单，但允许批量复制技术包和工作包。

### 6.3 订单级公共工作包

少量无法合理拆分的事项可挂在订单级，例如：

- 多樘门共用的一批板材
- 同批外协处理
- 共用包装或运输
- 项目级测量或安装服务

公共工作包的数量和成本必须按配置规则分摊回门樘，不能只停留在订单总账。

## 7. 角色与责任

### 7.1 下料负责人

- 编制并确认生产技术包
- 确认构件、材料、图纸、工艺和供应方式
- 指定采购或外协经办人
- 评估生产变更对材料、工艺、成本和交期的影响
- 技术包确认后无需第二人审批即可释放备料和生产

### 7.2 整单负责人

- 对具体门樘的生产协调和计划完工负责
- 分派内部工作和处理局部开工
- 解决缺料、人员、设备和技术异常
- 组织质量返工
- 确认整单完成并提交成品质检
- 不代替执行人员录入工作完成，不自行判定质检合格

### 7.3 执行人员

- 接收、开始、暂停和完成自己的任务
- 填写实际完成数量
- 上报缺料、报废、图纸问题、设备故障和其他异常
- 对需要检验的成果提交待检

### 7.4 采购或外协经办人

- 经办人可以是下料人员或采购人员
- 第一版经办人可以自主选择供应商和直接下单，不设置金额审批
- 负责价格、交期、催货、退补货和外协在途跟踪
- 操作必须进入统一采购和应付台账

### 7.5 仓库人员

- 登记到货数量和待检状态
- 办理合格品入库、预留、备料、发料、退料、盘点和报废
- 按领料清单逐项确认实发数量
- 确认发料后立即扣减库存，不要求领料人二次确认
- 办理成品入库和发货出库

### 7.6 独立质检人员

- 执行来料、过程和成品质检
- 决定合格、部分合格、不合格或让步接收
- 复检返工结果并关闭质量问题
- 不直接决定工资扣减

### 7.7 发货人员

- 根据订单交期和成品库存主动建立发货计划
- 协调销售确认客户收货条件
- 安排车辆、物流、装车、运输和签收
- 在财务放行后发起仓库出库

### 7.8 财务人员

- 确认客户收款到账
- 登记供应商、外协和物流付款
- 管理发货财务放行和欠款催收
- 审核工资和费用

### 7.9 销售

- 创建客户订单和门樘清单
- 下达生产订单
- 发起生产变更并与客户确认费用和交期
- 配合发货人员确认客户侧条件
- 不直接确认收款到账和成品质检合格

## 8. 生产技术包

### 8.1 内容

生产技术包包含：

1. 产品快照：产品、尺寸、材料、颜色、门型、开向、数量、交期。
2. 图纸文件：最终 DXF、激光图、折弯图、开槽图、外协图和参考图片。
3. 构件与物料：门扇、门框、门套、骨架、玻璃、花件、五金、包装等。
4. 工作包网络：内部加工、采购、外协、备料和装配任务及依赖。
5. 控制要求：检验标准、开工条件、装配条件、版本和特殊说明。

### 8.2 确认和冻结

- 下料人员点击确认后生成冻结版本，如 `V1`。
- 满足条件的工作包立即释放至相关岗位。
- 原参数、图纸、构件和用料不得直接覆盖。
- 未确认的草稿不产生正式采购、领料或生产执行任务。
- 同一时刻每樘门只有一个有效技术包版本。
- 第一版由下料人员依据终审图纸手工建立构件、材料和工作包，不自动从 CAD 生成 BOM 或生产工艺。

### 8.3 构件树

默认构件示例：

```text
门樘生产单
├── 正门扇
│   ├── 正面板件
│   ├── 反面板件
│   ├── 骨架
│   ├── 花件
│   └── 锁具与拉手
├── 子门扇
├── 门框
├── 门套/门头门柱
├── 气窗/玻璃
├── 安装辅材
└── 包装与随货物品
```

构件类型可配置，可增加门机、铜雕、发光字、铝艺装饰和电子设备等内容。

## 9. 工作包与工艺路线

### 9.1 通用工作包字段

- 名称、类别和关联构件
- 规格、数量、单位
- 获取方式
- 负责人、执行人和协作人
- 计划开始、计划完成、最迟到位日期
- 输入材料和输出成果
- 前置条件、后续影响和允许部分完成标识
- 阻塞节点：预拼、总装、质检、包装或发货
- 图纸、附件和当前技术版本
- 预计成本、实际成本和计件规则
- 检验策略和验收要求
- 状态、异常、返工和操作历史

### 9.2 获取方式

- 库存领用
- 直接采购
- 定制采购
- 内部加工
- 外协加工
- 库存后加工
- 组合装配
- 服务作业
- 待分派

### 9.3 路线模板示例

路线由配置生成，不固化为系统唯一流程：

```text
普通板件：剪板 → 折弯 → 油漆
精雕板件：剪板 → 折弯 → 精雕 → 油漆
蚀刻板件：剪板 → 折弯 → 蚀刻 → 油漆
激光件：激光切割 → 折弯 → 焊接/表面处理
骨架：型材备料 → 切割 → 焊接 → 校正
玻璃：定尺寸 → 下单 → 到货 → 来料检验 → 入库
花件：采购/定制 → 到货 → 检验 → 入库 → 领料
装配：预拼 → 补件 → 总装 → 调试
```

下料人员可以增删步骤、调整先后、切换内部或外协，并将成熟配置保存为模板。

### 9.4 依赖关系

- 强依赖：前项完成后才能开始。
- 并行：多个工作包可同时推进。
- 部分满足：主体内容到位后允许局部开工。
- 节点必需：不阻塞预拼，但必须在总装、质检或发货前完成。

系统据此计算：

- 可备料
- 可加工
- 可预拼
- 可总装
- 可提交成品质检
- 可包装
- 可入库

每个结论必须能展开显示已满足和未满足条件。

### 9.5 工作包状态

```text
草稿 → 待安排 → 已安排 → 进行中 → 已完成
                         ├── 暂停/异常
                         ├── 待检
                         ├── 待返工
                         └── 已取消
```

需要独立检验的工作，执行人提交后进入待检；检验合格后才成为可用成果。

## 10. 门樘主状态与风险标签

### 10.1 门樘主状态

```text
待生产确认
→ 技术准备中
→ 备料与加工中
→ 可局部装配
→ 总装中
→ 待成品质检
→ 返工中（可循环）
→ 待成品入库
→ 已入库待发货
→ 待财务放行
→ 待出库
→ 运输中
→ 已签收
```

主状态由关键业务事实自动汇总，普通用户不能任意跳转。

### 10.2 风险标签

风险标签与主状态独立，可同时存在多个：

- 缺料
- 外协延期
- 技术待确认
- 生产异常
- 质量返工
- 交期风险
- 收款未满足
- 客户暂缓
- 发货异常
- 版本变更中

## 11. 供应、采购与外协

### 11.1 供应需求

技术包确认后，工作包自动形成供应需求，记录：

- 来源订单、门樘、构件和工作包
- 品名、规格、数量、单位和图纸版本
- 需求日期、最迟到位日期和优先级
- 是否关键及阻塞节点
- 提出人、经办人和验收要求
- 预计成本、实际成本和状态

### 11.2 库存优先判断

```text
可用库存 = 账面库存 - 已预留 - 待检 - 不合格 - 冻结
```

- 库存足够：预留给门樘。
- 部分足够：预留现有数量，缺口转采购。
- 无库存：全部转采购或外协。
- 专用件到货后自动预留给来源门樘。

### 11.3 采购合并

- 相同或兼容需求可按供应商、物料和交期合并。
- 合并后保留每条需求来源和分配数量。
- 支持分批到货、部分取消、补货和价格分摊。
- 经办人第一版可直接下单，变更价格、数量和供应商必须留痕。

### 11.4 外协跟踪

- 发出原料或半成品及数量
- 加工内容、图纸版本和计价方式
- 发出日期、承诺回厂日期和当前持有方
- 分批回厂、损耗、补做、返工和报废
- 外协费用及来源门樘分摊

## 12. 来料检验与仓储

### 12.1 来料处理

```text
到货登记 → 待检区 → 来料检验 → 合格入库
                         ├── 部分合格
                         └── 退货/补货/返工/让步接收
```

- 仓库登记实到数量。
- 质检人员判定质量结果。
- 只有合格数量进入可用库存。
- 让步接收必须记录授权人和原因。

### 12.2 检验策略

- 必须检验
- 抽样检验
- 免检入库
- 异常触发强制检验

检验模板可按玻璃、花件、精雕件、蚀刻件、油漆件、五金、板材型材等配置。

### 12.3 库存分类与状态

库存分类：

- 原材料
- 配件与五金
- 在制品
- 成品

库存状态：

- 可用
- 已预留
- 待检
- 不合格
- 冻结
- 外协在途
- 已领用
- 余料
- 已出库

库存以仓库、库区、库位和批次追踪。

### 12.4 领料

```text
工作包提出需求
→ 生成领料清单
→ 仓库逐项确认实发数量
→ 仓库确认发料
→ 扣减库存并计入门樘成本
```

- 不要求领料人二次确认。
- 必须记录领取人或班组。
- 支持分批领料、追加、替代、退料、损耗和报废。
- 替代料和超额领料必须填写原因。

## 13. 生产协同与局部开工

### 13.1 三级计划

- 客户订单：总交期和分批交付计划。
- 门樘生产单：计划开工、计划完工和优先级。
- 工作包：到位、开始和完成时间。

第一版采用软排单：主管和整单负责人人工安排，系统提示任务过载、人员冲突和交期风险，不自动替人决定排产。

### 13.2 执行任务

执行人可以：

- 接受、开始、暂停和恢复
- 提交部分或全部完成
- 填写实际完成数量
- 上报异常
- 上传图片和加工文件

普通完成不强制填写大段说明；发生数量差异、报废、返工、设备或图纸问题时必须填写原因。

### 13.3 局部开工

系统分别判断预拼和总装条件。例如主体骨架和板件齐备时允许预拼，不必等待玻璃、拉手等后装件。

整单负责人可申请带条件开工，必须记录：

- 当前缺少项目
- 风险说明
- 预计补齐日期
- 不允许执行的后续节点

系统持续显示欠件，直到补齐或通过变更取消。

### 13.4 进度与预测

- 不允许手工填写模糊进度百分比作为唯一事实。
- 进度来自工作包完成数量、关键权重、异常和依赖关系。
- 第一版提供规则型预计完成日期和交期风险提示。
- 后续积累真实工时后再加入自动排产和更复杂预测。

## 14. 异常管理

异常独立于任务状态，至少支持：

- 缺料
- 图纸或尺寸问题
- 设备故障
- 加工失败
- 外协延期
- 来料不合格
- 人员安排问题
- 客户变更
- 质量返工
- 其他阻塞

每个异常记录：

- 关联门樘和工作包
- 严重程度
- 提出人、处理人和解决期限
- 临时措施和最终结果
- 对成本、工资和交期的影响
- 图片和附件

整单负责人关闭普通生产异常；质量异常必须由质检人员确认关闭。

## 15. 生产变更与版本

### 15.1 变更流程

```text
销售发起生产变更
→ 下料人员评估材料、工艺、采购、成本和交期
→ 销售与客户确认费用和新交期
→ 已开工时由整单负责人安排暂停和切换
→ 生成新技术包版本并生效
```

### 15.2 影响处置

对受影响内容逐项选择：

- 继续使用
- 改制
- 补料
- 退料
- 退货
- 转公共库存
- 作废或报废
- 追加采购或外协

### 15.3 规则

- 原版本永久保留，形成 `V1/V2/V3`。
- 未开始工作包切换到新版本。
- 进行中工作包先暂停并由负责人决定处置。
- 已发生采购、领料、成本和工资不得直接删除。
- 客户变更重做与质量返工必须分开记录。
- 非生产字段可直接修改，但保留操作历史。

## 16. 质量与返工

### 16.1 检验类型

- 来料检验
- 过程检验
- 成品质检
- 返工复检

### 16.2 检验方式

- 无需检验
- 执行人自检
- 整单负责人确认
- 独立质检
- 抽样检验
- 必须填写实测值

### 16.3 成品质检

- 所有成品质检前必需工作完成后，由整单负责人提交待检。
- 独立质检人员判定合格或不合格。
- 不合格时登记质量问题，整单负责人组织返工。
- 执行人员完成返工后提交复检。
- 原质检记录不覆盖，按次数新增。
- 全部问题关闭后才允许成品入库。

### 16.4 质量问题分级

- 一般：现场可立即修复，不影响总体交期。
- 重要：必须返工和复检，禁止成品入库。
- 严重：涉及尺寸、结构、安全或重大外观，需要主管介入或重制。

## 17. 成品入库、发货和签收

### 17.1 成品入库

- 成品质检合格后生成待入库任务。
- 仓库核对成品编号、当前版本、数量、包装、随货件和照片。
- 每樘门生成独立成品编号和二维码预留字段。
- 未包装完成可进入待包装区，但不能成为可发货库存。

### 17.2 发货计划

发货人员根据交期和库存主动建立计划，销售确认：

- 地址、联系人和电话
- 客户是否同意收货
- 到货、卸货和安装条件
- 包装和随货文件
- 暂缓发货要求

发货人员维护车辆、司机、物流、运费、装车、运输状态和签收资料。

### 17.3 财务放行

仓库出库必须满足：

- 成品已入库
- 包装已完成
- 销售已确认客户条件
- 达到本次发货要求的累计有效收款
- 发货计划已确认

特殊授权放行记录欠款差额、原因、申请人、批准人和承诺收款日期；仅解锁本次发货，不改变欠款。

### 17.4 出库与签收

- 仓库按成品编号逐项核对装车并扣减成品库存。
- 车辆离厂后状态为运输中。
- 客户签收后门樘状态变为已签收。
- 所有门樘签收后，客户订单才进入已交付。
- 尾款未结清时同时进入催收清单。

## 18. 应收、应付和费用

### 18.1 收款计划

每个订单从模板生成，也可单独调整。模板示例：

- 50% 定金，发货前付清
- 30% 定金，生产前 30%，发货前 40%
- 30% 定金，发货前 60%，验收后 10%
- 发货前一次性付清
- 月结
- 自定义

收款节点支持比例或固定金额，记录触发条件、应收日期、已收金额、凭证和是否为发货条件。

### 18.2 收款规则

- 节点应收合计必须等于订单金额。
- 一笔收款可分配多个节点，一个节点可分多次收款。
- 销售登记后为待财务确认，财务确认后才计入有效收款。
- 已确认收款只能冲销，不能直接覆盖。
- 修改订单金额时必须重新校验未完成节点。

### 18.3 应付和付款

- 采购、外协、物流验收或确认后形成应付草稿。
- 经办人自主下单，但付款状态由财务登记。
- 支持部分付款、账期、发票状态和凭证。
- 应付金额按来源关系分摊到订单和门樘成本。

### 18.4 费用

员工垫付的采购、运输和临时加工费用可登记费用记录，关联订单、门樘或工作包，并由财务确认报销。

## 19. 成本核算

### 19.1 门樘实际成本

```text
材料领用
+ 采购专用件
+ 外协加工
+ 计件工资
+ 固定工资分摊
+ 包装运输
+ 返工损耗
+ 其他费用
= 门樘实际成本
```

### 19.2 成本来源

- 材料：实发数量乘批次成本，退料冲减。
- 采购：到货数量、实际价格和附加费用。
- 外协：验收数量和结算金额。
- 工资：已审核计件工资及固定工资分摊。
- 包装运输：按门樘或配置方式分摊。
- 返工：补领、报废、外协补做和返工工资。

### 19.3 预计与实际

技术包确认形成预计成本，执行过程形成实际成本。系统突出数量、单价、损耗、外协和工资差异。

## 20. 固定工资与计件工资

### 20.1 工资结构

```text
应发工资 = 固定工资 + 已审核计件工资 + 奖金/补贴 - 扣款
```

第一版不做复杂考勤、社保和个税，仅生成生产相关工资草稿与结算记录。

### 20.2 计件规则

支持：

- 按樘
- 按件
- 按平方米
- 按延米
- 按重量
- 固定工序价
- 特殊任务人工核价

第一版只配置当前实际使用规则，同一工作内容不按产品、厚度、尺寸或复杂度自动变价。

### 20.3 计件生成

- 执行人提交完成后形成计件草稿。
- 无质检要求的由负责人确认。
- 有质检要求的在检验合格后生效。
- 多人可按数量、比例、主辅或指定金额分配。
- 客户变更重做、质量责任返工和非责任返工采用不同处理类型。
- 月度审核后锁定，只能通过调整记录修正。

## 22. 数据一致性规则

- 已确认技术包、库存流水、质检、收付款、成本和工资不得物理覆盖。
- 数量和金额变更通过新流水、冲销或调整记录实现。
- 门樘状态由事实数据汇总，不允许普通页面直接写任意状态。
- 所有跨订单采购和费用必须保留来源分配。
- 所有文件保存内容哈希、上传人、时间和业务版本。
- 关键确认接口必须支持幂等请求，避免重复点击生成重复采购、入库或成本。
- 取消业务必须检查后续单据，必要时采用反向业务而不是删除。

## 24. 权限与敏感数据

权限拆成业务能力，不与单一岗位强绑定：

- 技术包查看、编辑、确认
- 工作分派、执行、异常关闭
- 采购下单、改价和取消
- 收货、质检、入库、发料、退料和报废
- 成品质检、让步接收和返工关闭
- 成品入库、发货和出库
- 收款确认、付款登记和特殊放行
- 工资规则、工资审核和工资查看
- 成本、售价和毛利查看
- 模板和基础资料管理

售价、毛利、工资和支付账户采用独立权限，普通执行人员不默认可见。

## 25. 通知与事件

通知由业务事件触发：

- 新任务分派和工作包可开工
- 技术包确认或版本变化
- 缺料、到货、待检和外协延期
- 任务即将逾期或已逾期
- 质量不合格、返工和复检
- 成品待入库、待发货和运输异常
- 收款不足、特殊放行和欠款催收

通知优先进入系统待办中心。普通状态变化不使用阻塞弹窗；错误、关键确认和授权使用明确反馈。企业微信、短信和邮件作为后续扩展。

## 26. 审计、安全与备份

- 所有关键操作记录用户、时间、来源 IP、业务对象和前后差异。
- API 统一要求 Door ERP 登录认证和后端权限校验。
- 附件下载按业务对象权限控制。
- 金额、工资和个人信息不写入普通日志。
- 数据库和附件分别备份并定期验证恢复。
- 关键业务表使用软取消或反向流水，不提供普通物理删除。

## 28. 错误处理

- 业务校验错误返回明确中文原因和可处理建议。
- 并发修改使用版本号或更新时间检测，避免后提交覆盖先提交。
- 网络重试不得重复生成采购、入库、收款和工资流水。
- 文件上传失败与主业务确认分开处理，避免出现业务成功但页面误报失败。
- 所有失败操作保留关联请求编号，日志不泄露密码、令牌和完整敏感数据。

## 29. 分阶段建设

业务模型按本设计一次确定，开发按以下阶段交付。

### 阶段 0：隔离与骨架

- 停用旧生产入口和 ERPNext 同步入口
- 建立新模块、权限、编号和审计基础
- 新旧数据隔离
- 建立客户订单和多门樘生产单

验收：销售可从终审结果创建包含多樘门的订单，每樘生成独立编号，旧模块不再接收新数据。

### 阶段 1：技术包和生产协同

- 技术包版本、构件树、文件和确认
- 可配置工作包、路线模板和依赖
- 整单负责人、执行任务、局部开工和异常中心
- 生产变更单和版本切换

验收：一樘门可从技术准备推进到提交成品质检，所有执行记录和变更可追溯。

### 阶段 2：供应、采购、外协和仓储

- 物料、供应商、供应需求和库存判断
- 合并采购、定制采购和外协
- 到货、来料检验、入库、预留和领料
- 退料、损耗、报废和库存流水

验收：多个门樘需求可合并采购，到货后按来源预留并按清单发料，账面库存和实际成本联动。

### 阶段 3：质量、成品和交付

- 来料、过程、成品检验模板
- 质量问题、返工和复检
- 成品入库、包装、发货计划、出库和签收
- 运输异常

验收：不合格成品无法入库，未入库成品无法发货，每个成品编号可追溯到门樘和技术版本。

### 阶段 4：收付款、成本和工资

- 收款模板、订单收款节点和财务确认
- 特殊发货放行
- 应付、付款和费用
- 门樘预计/实际成本
- 固定工资和基础计件工资

验收：未满足收款条件时系统阻止出库；门樘可查看实际材料、采购、外协和工资成本；工资可按月审核锁定。

### 阶段 5：优化

- 二维码和移动端快速操作
- 企业微信等外部通知
- 真实工时和产能数据
- 自动排产、预测和更细经营分析

## 30. 测试策略

### 30.1 单元测试

- 编号和版本生成
- 依赖和开工条件计算
- 库存可用量、预留和扣减
- 采购合并与来源分配
- 收款节点和发货放行判断
- 成本和计件工资计算
- 状态汇总和风险标签

### 30.2 集成测试

- 多门樘订单下达至技术包确认
- 并行采购、外协、内部加工和局部开工
- 分批到货、来料不合格、补货和领料
- 生产变更对在制、采购、库存和工资的影响
- 成品质检不合格、返工和复检
- 成品入库、收款不足、特殊放行、出库和签收

### 30.3 权限测试

- 执行人不能确认质检、收款或工资
- 仓库不能绕过检验使用不合格库存
- 销售不能直接确认到账
- 未授权用户不能查看工资、售价和毛利
- 已确认关键记录不能直接删除或覆盖

### 30.4 端到端验收样例

使用一个包含三樘不同门的客户订单：

1. 三樘分别建立技术包，其中一樘包含玻璃和花件采购，一樘包含蚀刻外协。
2. 合并通用配件采购，保留每樘来源。
3. 分批到货，其中一项来料不合格并补货。
4. 主体材料齐备后局部预拼，后装件晚到。
5. 仓库分批发料并形成实际成本。
6. 一樘发生客户生产变更并生成 `V2`。
7. 一樘成品质检不合格，经返工复检后入库。
8. 发货前收款不足，财务确认到账后放行。
9. 分批发货并完成签收。
10. 检查门樘成本、采购来源、库存流水、质量记录和计件工资均可追溯。

## 31. 成功标准

- 任意门樘能在一个页面看到当前版本、进度、缺项、异常、成本和责任人。
- 下料人员确认技术包后，可并行释放采购、外协、备料和内部加工。
- 材料未全部到齐时，系统能明确判断是否允许预拼或总装。
- 任何库存数量都可追溯到入库、预留、领料、退料和出库流水。
- 任何采购、外协、工资和质量记录最终可追溯到具体门樘。
- 生产变更不覆盖历史，现场只执行当前有效版本。
- 质检不合格不能入库，收款不满足不能出库，特殊授权完整留痕。
- 现场人员完成常规任务的操作不超过少量关键输入。
- 新增花件、工艺或供应路线主要通过配置完成，不要求修改主流程代码。
