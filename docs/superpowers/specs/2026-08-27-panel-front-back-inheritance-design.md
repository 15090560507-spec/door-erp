# 门板正反面继承与子门独立设置设计

## 目标

在不改变现有门板几何绘制算法的前提下，减少正反面相同门板的重复录入，并补齐子门正反面可以分别配置的能力：

1. 主门反面可以选择“同正面”，勾选后无需重复填写。
2. 子门拆分为“子门正面”和“子门反面”，子门反面同样可以选择“同正面”。
3. 正反面独立时，继续支持各自的样式、分区、填充、玻璃图案和尺寸参数。
4. 历史订单保持原来的绘图结果，不因新增默认值而改变。
5. 澄清玻璃线条参数含义，降低表单误解。

## 主门正反面规则

新增布尔字段 `back_panel_same_as_front`。

- 新建订单默认勾选。
- 勾选时，反面门板实时使用正面的全部门板参数，不把正面值复制到反面字段中。
- 正面参数修改后，反面绘图立即随之变化。
- 取消勾选时，显示完整的反面门板设置，允许独立配置。
- 独立反面设置继续保存，重新勾选不会清空；以后再次取消勾选时可以恢复此前输入。

“全部门板参数”包括：

- 门板样式和固定款式解析结果。
- 两列式、三列式、H 型、H+ 型、横向分区、大板和圆盘等布局参数。
- A/B/C 区宽度、高度、偏移量和填充。
- B2、B4 玻璃图案。
- 玻璃图案外边距和图案内部线距。
- 圆盘半径等样式专用参数。

主门以外的拉手、指纹锁、磁力锁、开启机构等配件仍按各自正反面业务规则绘制，不因“反面同正面”而复制配件。

## 子门正反面规则

现有 `child_door_panel_style` 及其配套字段定义为“子门正面设置”。新增：

- `child_back_same_as_front`
- `child_back_door_panel_style`
- 一套与子门正面对应的反面布局、分区、填充、玻璃图案和样式专用参数。
- 子门正面和反面各自的玻璃图案外边距、图案内部线距。

行为规则：

- 仅在子母门、两定两开、四开门等存在子门或固定扇门板的门型中显示。
- 新建订单的“子门反面同正面”默认勾选。
- 子门正面样式为空时，沿用当前“子门不单独增加造型”的兼容行为。
- 勾选“子门反面同正面”时，反面子门实时使用子门正面的全部参数。
- 取消勾选时，显示独立的子门反面设置。
- 主门的“反面同正面”与子门的“反面同正面”互不影响。

## 表单结构

门板设置保持清晰的四段结构：

1. 正面门板
2. 反面门板
3. 子门正面（存在子门时）
4. 子门反面（存在子门时）

反面段标题旁使用复选框：

- `反面同正面`
- `子门反面同正面`

勾选后收起对应反面参数，只显示“已沿用正面的全部门板设置”的简短状态。取消勾选后展开完整参数。

原标签调整为：

- `玻璃线条边距` 改为 `玻璃图案外边距(mm)`。
- `玻璃线条间距` 改为 `图案内部线距(mm)`。

参数含义：

- 玻璃图案外边距：B2/B4 玻璃区域边界到最外层装饰线的距离。
- 图案内部线距：双边框、四角回纹等多层图案内部各组线条之间的基础间距。

历史数据中的反面数值 `0` 继续表示沿用正面；新建独立反面设置使用明确数值，界面不再要求用户理解 `0` 的隐含语义。

## 后端与绘图选择

后端模型新增上述字段，但不修改数据库结构；字段继续保存在任务 JSON 参数中。

绘图阶段统一按“门板归属 + 正反面”选择设置：

- 主门正面：主门正面参数。
- 主门反面且同正面：主门正面参数。
- 主门反面且独立：主门反面参数。
- 子门正面：子门正面参数。
- 子门反面且同正面：子门正面参数。
- 子门反面且独立：子门反面参数。

目前子门绘图会在判断正反面之前直接选用同一套子门设置，本次需要调整这一参数选择顺序。具体线条、填充、玻璃图案的几何生成函数保持不变。

## 兼容策略

新建订单与历史订单采用不同的缺省来源：

- 前端新建表单默认 `back_panel_same_as_front=true`、`child_back_same_as_front=true`。
- 后端模型默认两个字段为 `false`。
- 历史任务缺少字段时按 `false` 处理，继续使用原有独立反面设置，避免历史 DXF 变化。
- 旧版 API 请求未携带字段时也保持原行为。
- 旧的反面玻璃参数 `0=沿用正面` 逻辑保留。

## 测试

1. 新建表单默认勾选主门和子门“反面同正面”。
2. 主门勾选时，修改正面样式、分区、填充和玻璃参数后，反面绘图同步变化。
3. 主门取消勾选时，反面使用独立参数。
4. 子门勾选时，反面子门使用子门正面参数，而不是主门正面参数。
5. 子门取消勾选时，正反子门可以生成不同门板布局。
6. 拉手、指纹锁和开启机构不因门板继承而错误复制。
7. 历史 payload 不含新增字段时，绘图结果保持原逻辑。
8. 历史反面玻璃参数为 0 时，仍正确沿用正面数值。
9. 前端构建、后端模型校验和现有 CAD 回归测试通过。

## 不在本次范围

- 不修改门板线条、填充和玻璃图案的几何算法。
- 不修改拉手、锁具、开启机构和其他配件的正反面规则。
- 不进行数据库迁移。
- 不改动历史订单数据。
