# CAD 遮挡关系与正反面线稿双通道提取设计

## 1. 背景与目标

本次设计包含两个相互独立、但共同服务于门类图纸输出和效果渲染的功能：

1. 在图纸绘制表单末尾增加可选的 CAD 遮挡关系。开启后，打印和查看时按门板、门框、门套或门头门柱的层级隐藏被覆盖线条，同时保留完整原始实体。
2. 在效果渲染中增加正面、反面线稿双通道提取。既可以从系统已有图纸任务直接生成干净线稿，也可以从整张订货单图片中识别并裁出正反面线稿。

目标是提高打印图纸的层次清晰度，并减少效果渲染前人工裁图的工作量。不得通过重画门体或拆分原始构件来获得视觉效果。

## 2. 范围与约束

### 2.1 本次范围

- 图纸绘制表单增加“启用遮挡关系”开关，默认关闭。
- 正面和反面图纸均支持遮挡关系。
- 门板、门框、门套、门头门柱之间按固定层级处理遮挡。
- 配件、文字和尺寸标注始终可见。
- 效果渲染支持“关联项目图纸”和“上传整张订货单”两种线稿来源。
- 提取结果固定为“正面线稿”和“反面线稿”两张独立图片。
- 提交效果渲染前只能选择其中一张作为当前任务线稿。
- 上传识别结果允许用户手动调整正反面裁剪区域并重新提取。

### 2.2 不在本次范围

- 不修改门体尺寸、门型、标注和报价计算规则。
- 不拆分门板、门框或门套的原始闭合实体。
- 不让生成式 AI 重新绘制或补画 CAD 线稿。
- 不改变现有效果渲染 Provider 请求协议。
- 不把正面和反面线稿默认同时发送给图片模型。
- 不承诺任意未知订货单图片都能完全自动、零校正提取。

## 3. CAD 遮挡关系

### 3.1 表单行为

- 在图纸绘制表单最后增加“启用遮挡关系”开关。
- 默认值为关闭。
- 老任务缺少该字段时按关闭处理，保证历史图纸输出不变。
- 开关状态随任务数据保存，重新进入绘制页面时保持原选择。

### 3.2 显示层级

开启遮挡后，显示和打印顺序由下至上为：

1. 门板及门板填充。
2. 门框遮挡面。
3. 门框线条。
4. 门套或门头门柱遮挡面。
5. 门套或门头门柱线条。
6. 拉手、锁具、合页等配件。
7. 文字和尺寸标注。

遮挡仅作用于门板、门框、门套和门头门柱之间。配件、文字和标注不得被这些遮挡面覆盖。

### 3.3 实体保留原则

- 门板、门框、门套和门头门柱继续使用当前完整实体。
- 不裁断被覆盖线条，不把一个闭合矩形或圆弧轮廓拆成多个显示实体。
- 遮挡仅通过新增 WIPEOUT 实体实现。
- 原始门板仍应能够一次选中，原始框体也保持可编辑。

### 3.4 遮挡图层

- 新增独立图层 `A-DOOR-OCCLUSION`。
- 所有构件层级遮挡面都放在该图层。
- 遮挡边界不显示且不打印。
- 正常显示和打印时遮挡生效。
- 用户关闭或冻结 `A-DOOR-OCCLUSION` 后，应能看到完整原始线条。
- 现有配件遮罩可继续使用其既有图层和规则，不与构件遮挡层混用。

### 3.5 遮挡轮廓

- 遮挡面沿上层构件的真实外轮廓生成，不使用覆盖范围过大的通用矩形。
- 直线构件使用闭合多边形轮廓。
- 圆弧门、弧形气窗和弧形门套使用与实际弧线一致的离散闭合轮廓。
- 斜门套、01 款、03 款及其他已有门套款式使用各自实际外轮廓。
- 门头和左右门柱分别生成对应矩形或闭合轮廓，不合并为覆盖整门的大遮罩。

### 3.6 绘制顺序

- DXF 中必须明确写入实体绘制顺序，不能只依赖实体创建先后。
- 门框遮挡面位于门板之上、门框线条之下。
- 门套或门头门柱遮挡面位于门框之上、门套或门头门柱线条之下。
- 配件、文字和标注统一放在上述构件之后。
- 若目标 DXF 库无法稳定写入排序表，则必须通过可验证的实体顺序回退，并在 AutoCAD 2022 中确认显示和打印结果。

## 4. 正反面线稿双通道

### 4.1 统一输出

无论使用哪一种来源，后端统一返回：

- 正面线稿文件及访问地址。
- 反面线稿文件及访问地址。
- 两张图片的宽度、高度和提取置信度。
- 原图中的正面、反面裁剪区域。
- 是否需要人工确认。
- 提取来源和失败原因。

正面和反面必须是两张独立图片，不输出默认合并图。

### 4.2 通道 A：关联项目图纸

1. 用户在效果渲染页面选择已有图纸任务。
2. 后端读取该任务已经生成或可重新生成的 DXF/SVG 数据。
3. 根据既有正面、反面绘图区间分别导出。
4. 保留门板、门框、门套、填充和配件等可见构件。
5. 过滤尺寸标注、文字、表格、标题栏及辅助图层。
6. 输出两张无压缩或无损压缩的高清 PNG。

该通道基于结构化图层和已知视图坐标，是优先级最高、精度最稳定的线稿来源。

### 4.3 通道 B：上传整张订货单

1. 原图按原始质量上传并保存，不做有损压缩。
2. 检测图片方向并纠正旋转；需要时执行透视校正。
3. 识别已知订货单模板，或通过 OCR 定位“正面”“背面”等锚点。
4. 检测门体外框和主要绘图区，排除标题、产品照片、参数表和备注区。
5. 分别提取正面和反面候选区域。
6. 清理裁剪框外的尺寸、文字和引线；框内内容以保留为优先，不使用生成式 AI 重画。
7. 返回预览和置信度。
8. 置信度不足或缺少其中一面时，要求用户手动调整裁剪框后重新提取。

已知模板使用专门规则提高精度；陌生模板使用通用检测并强制提供人工校正入口。

### 4.4 预览与选择

- 页面同时显示正面、反面两个提取结果。
- 两张图均可点击放大查看。
- 用户可以回到原图调整两个裁剪框、旋转、重置并重新提取。
- 使用单选控件选择“正面”或“反面”。
- 提交渲染任务时只上传当前选中的一张线稿。
- 切换选择不需要重新提取图片。

## 5. 模块边界

### 5.1 CAD 遮挡构建器

职责：接收已计算完成的构件轮廓，生成遮挡面、图层和绘制顺序。

不负责：门型尺寸计算、框宽计算、门板分区、配件放置、标注内容和报价逻辑。

### 5.2 线稿提取服务

职责：接受项目任务或上传图片，执行对应提取策略并返回统一结果。

内部策略：

- 项目图纸导出策略。
- 已知模板图片策略。
- 通用图片检测策略。
- 人工裁剪确认策略。

### 5.3 效果渲染页面

职责：选择线稿来源、展示提取预览、接受人工校正、选择正面或反面并提交现有渲染任务。

不负责：保存 API Key、直接请求图片模型、在浏览器内生成最终线稿。

### 5.4 Provider 层

Provider 继续接收已确认的单张线稿和现有参考素材。线稿提取逻辑不得进入 Provider，也不得改变当前请求格式。

## 6. 文件与生命周期

- 项目图纸导出的线稿可作为渲染任务临时文件保存。
- 上传的原始订货单、候选裁剪图和确认后的正反面线稿均与当前渲染任务或临时会话关联。
- 临时文件沿用现有效果渲染临时文件清理规则。
- 历史任务仅保存实际使用的线稿引用和必要的提取元数据。
- 所有文件访问继续要求登录并经过后端鉴权。

## 7. 错误处理

- 未找到正面或反面时，返回缺失的具体视图，不返回笼统的“识别失败”。
- 置信度不足时返回 `needsReview`，前端不得自动提交渲染。
- 图片模糊、方向错误、透视严重或分辨率不足时返回可理解的原因。
- 关联项目缺少可用 DXF/SVG 时，提示用户改用上传通道。
- 提取失败保留原始上传文件，允许重新框选，不清空页面其他素材。
- 线稿提取错误不得修改或覆盖效果渲染模型配置。
- 图片模型调用错误继续沿用现有 Provider 错误处理。

## 8. 验收标准

### 8.1 CAD 遮挡

- 默认关闭，旧任务导出结果与改造前一致。
- 开启后，打印结果不显示被上层构件覆盖的线条。
- 关闭或冻结 `A-DOOR-OCCLUSION` 后可看到完整原始构件。
- 门板保持完整闭合实体并可一次选中。
- 配件、文字和尺寸标注始终可见。
- 正面、反面及主要门型均按相同层级工作。
- 直门、圆弧门、弧形气窗、门套和门头门柱均有测试样例。
- AutoCAD 2022、系统预览和 PDF 打印结果一致。

### 8.2 线稿提取

- 关联项目可以生成两张独立线稿，且不含尺寸、标题栏和参数表。
- 提供的订货单样例可以正确提取正面和反面。
- 识别不确定时明确要求人工确认。
- 用户可以调整两个裁剪框并重新提取。
- 正面、反面均可放大查看。
- 每次渲染请求只包含用户选中的一张线稿。
- 原始上传图片不被有损压缩。

## 9. 测试策略

- 单元测试：遮挡轮廓生成、图层归属、绘制顺序、默认关闭兼容性。
- DXF 结构测试：确认原始闭合实体保留、WIPEOUT 位于独立图层、正反面排序正确。
- 图像测试：固定样例的正反面裁剪坐标、输出尺寸、标注过滤结果。
- API 测试：两种来源的统一返回结构、缺面、低置信度和鉴权错误。
- 前端测试：来源切换、裁剪框调整、正反面单选、提交载荷只含一张图片。
- 人工验收：AutoCAD 2022 显示、打印 PDF、系统预览以及效果渲染提交全过程。

## 10. 分阶段实施

1. 实现 CAD 遮挡开关、独立图层、真实轮廓和绘制顺序。
2. 实现关联项目图纸直接导出正反面线稿。
3. 实现订货单已知模板识别、预览和人工裁剪校正。
4. 扩展模板规则，并为陌生模板增加通用检测辅助。

每一阶段独立验证，避免 CAD 遮挡问题与图像识别问题互相干扰。
