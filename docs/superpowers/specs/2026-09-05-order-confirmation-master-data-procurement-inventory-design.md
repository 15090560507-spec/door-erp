# 订单确认、基础资料、采购与库存工作台设计

## 目标

在 Door ERP 现有图纸、报价、生产履约和库存能力上，建立一条从销售确认到采购、仓储、生产和发货的共用单据链。系统采用“角色工作台 + 共用单据链”，不照搬传统 ERP 的超宽表格和重复录入方式。

本次新增或调整五个业务工作台：订单确认、生产管理、采购管理、库存管理、基础资料。图纸和报价仍保留现有入口。

## 一、总体业务链

统一链路如下：

`图纸任务 -> 报价单 -> 销售订单 -> 门樘生产任务 -> 物料需求 -> 采购单 -> 收货检验 -> 库存流水 -> 生产领料 -> 成品质检 -> 成品入库 -> 收款放行 -> 发货`

关键原则：

- 一张销售订单可包含同一客户的多张图纸、多樘门。
- 图纸进入“图纸绘制”阶段后即可加入订单草稿，不要求先完成报价。
- 正式确认订单必须完成报价并核对尺寸、数量、金额和交期，但不强制图纸已终审。
- 正式确认后进入生产管理“待下达”；某樘门只有在图纸终审通过后才允许下达生产。
- 同规格数量大于一时，下达生产后按每樘门生成独立生产编号和技术包。
- 采购允许跨订单合并，但每个采购数量仍分配到具体需求、订单和生产编号。
- 库存属于全厂，不属于某张订单；订单只保留预留、领用和实际消耗关系。
- 正式确认后的商务变化保留订单变更记录；下达生产后的技术变化必须走生产变更单。
- 所有关键单据使用不可变编号和时间戳，禁止通过覆盖历史数据改变已确认事实。

## 二、导航与角色工作台

顶部导航继续直接展示图纸、审核、效果渲染和报价等高频入口。在“报价系统”后增加“业务管理”菜单，包含：

1. 订单确认
2. 生产管理
3. 采购管理
4. 库存管理
5. 基础资料

用户可将业务管理中的常用工作台固定到顶部。固定偏好保存在当前用户设置中；第一版可使用浏览器本地存储，后续迁移到用户配置表。

现有生产管理中的采购中心、仓库中心和基础资料不再作为另一套业务页面继续扩展。生产页仅保留与当前订单或门樘相关的供应摘要和跳转入口，完整操作在对应角色工作台完成。

## 三、订单确认

### 3.1 使用范围

订单确认用于从同一客户的若干图纸任务中选择一部分，整理成一张销售订单。参考传统销售订单的信息完整性，但不复制其超宽、横向滚动的交互。

### 3.2 页面结构

订单确认包含三个页面：

- 订单看板：草稿、已确认、履约中、交期风险、待收款放行等汇总。
- 订单列表：按订单号、客户、项目、销售员、交期和状态检索。
- 订单详情：基础信息、门樘明细、金额与收款、风险检查、操作记录。

新建订单时从“候选图纸”抽屉选择任务。候选范围为已进入图纸绘制阶段、且未被其他草稿或已确认订单占用的任务；已取消订单中的任务可以重新选择。候选列表支持按客户、项目、门型、尺寸、图纸状态和报价状态筛选。一次订单只能选择同一客户的任务。

门樘明细采用纵向可展开行，不使用超宽表格。摘要显示：图纸任务、产品名称、门型、宽高、开向、颜色、数量、报价金额、图纸状态和版本；展开后显示完整商品、配置、价格和备注。

### 3.3 数据结构

销售订单 `sales_orders`：

- `id`、`order_no`、`order_date`
- `customer_name`、`project_name`、`delivery_address`
- `salesperson`、`delivery_date`
- `payment_template_id`、`remark`
- `status`：`draft`、`confirmed`、`fulfilling`、`completed`、`cancelled`
- `subtotal`、`discount_amount`、`total_amount`
- `created_by`、`created_at`、`updated_at`、`confirmed_at`
- `version`

门樘明细 `sales_order_door_lines`：

- `sales_order_id`、`line_no`
- `task_id`、`quote_id`、`quote_group_index`
- `product_name`、`door_type`、`width`、`height`、`opening_direction`
- `color`、`quantity`、`unit`、`unit_price`、`amount`
- `drawing_revision_snapshot`、`quote_snapshot`
- `remark`

收款节点 `sales_order_payment_nodes`：节点名称、应收比例或金额、计划日期、实收金额、实收日期和状态。订单可套用常用收款模板，也允许逐单调整。

订单操作记录 `sales_order_events`：保存创建、修改、确认、取消、下达和异常放行等事件。订单变更记录保存变更前后内容、原因、操作人和时间。

### 3.4 状态与校验

订单草稿允许存在未报价门樘。正式确认前必须满足：

- 至少包含一樘门。
- 所有明细属于同一客户。
- 每条明细均关联已保存报价。
- 客户、订单日期、交期、数量、宽高、单价和金额完整有效。
- 用户已在页面中央确认宽、高、数量和订单总金额。

正式确认时保存图纸版本和报价快照。订单确认后，原报价或图纸继续修改不会静默改变订单金额或订单参数；页面显示“来源已有新版本”，由用户发起订单变更。

订单只保存销售层状态。待下达、部分下达、生产中、待质检、待入库等进度根据门樘履约状态实时汇总，避免维护两套相互矛盾的状态。

### 3.5 与生产衔接

正式确认后，每条门樘明细进入生产管理“待下达”。图纸未终审时显示“等待图纸终审”，终审通过后才启用“下达生产”。下达时按数量生成独立门樘和生产编号，并记录来源订单、订单行、图纸快照和报价快照。

## 四、基础资料

### 4.1 工作台结构

基础资料包含两个主要页面：

- 物料与商品
- 供应商及供货

仓库和库位设置归入库存管理的设置页，避免基础资料入口继续膨胀。

### 4.2 物料与商品统一档案

现有物料档案升级为统一 `items` 主档，不为销售和采购重复建档。类型包括：定制成品、原材料、配件、半成品、耗材和外协服务。

每项资料可独立标记：可销售、可采购、管理库存、可外协。主要字段包括：

- 系统编码、名称、分类、规格型号、品牌、图片
- 基本单位、采购单位及换算率
- 默认仓库、默认库位、安全库存、最低库存
- 标准销售价、参考采购价
- 是否启用、备注

定制门仅建立产品模板，不按每一种尺寸建立商品。订单中的实际门型、尺寸、开向、颜色和配置保存在门樘明细快照中。

### 4.3 供应商与供货关系

供应商主档保存编号、名称、简称、联系人、电话、地址、开票资料、默认税率、结算方式、付款周期、默认交期、供应类别、合作状态和备注。

供应商与商品为多对多关系。`supplier_items` 保存：

- `supplier_id`、`item_id`
- 供应商货号、供应商商品名称、采购规格
- 采购单位、换算率、含税价、税率
- 最小采购量、标准交期、是否首选
- 最近采购价、最近采购日期、是否启用

商品详情可查看全部供应商；供应商详情可查看全部供货商品。两处操作同一条关系数据，不产生副本。

### 4.4 高效录入

- 支持复制现有商品或供应商。
- 支持 Excel 批量导入，并先预检错误再正式写入。
- 收货或采购时遇到新规格，可建立“待完善资料”，之后由资料维护人员补齐。
- 支持按系统编码、名称、规格、品牌和供应商货号组合检索。
- 选择商品后自动推荐首选供应商、最近采购价和标准交期。

## 五、采购管理

采购管理设置五个工作区：采购看板、需求池、采购订单、到货跟踪、采购分析。

需求来源包括生产物料需求、安全库存补货和人工采购需求。整单负责人可将需求指定为“本人联系”或“采购办理”；本人联系的项目不进入采购员待办，但仍记录经办人、预计到货和实际结果。

需求池支持按物料、供应商、交期和项目合并。创建采购单时必须保留 `purchase_allocations`，记录采购行数量分别覆盖哪些需求和生产编号。

采购单状态：草稿、已下单、部分到货、已到齐、已关闭、已取消。采购员负责供应商、价格、下单日期和预计到货；到货后只登记到货事实并生成仓库待收任务，不在采购页面重复办理库存入账。

采购分析包括供应商价格趋势、准时率、来料合格率、采购金额和异常次数。第一版优先保证交易链正确，分析使用现有数据派生，不提前建设复杂评分模型。

## 六、库存管理

库存管理设置六个工作区：库存看板、收货与来料检验、领料与退料、调拨盘点与报废、成品入库与出库、库存流水。

统一数量口径：

`可用库存 = 现存数量 - 已预留数量`

采购到货但未检验时属于待检数量，不进入可用库存。独立质检人员确认合格、让步接收或退货；合格数量入库后按订单交期优先满足预留需求。

生产领料按清单逐项办理，由仓库确认实际数量后直接记账，不要求领料人二次确认。退料、调拨、报废、外协发出和外协返回均生成不可变库存流水。

成品必须先完成独立质检，再办理成品入库。发货人员根据订单交期与销售沟通后发起出库；系统校验收款节点，未达到规定款项时禁止发货。特殊情况只允许通过授权放行，并记录授权人、原因和时间。

库存看板面向全厂展示现存、可用、已预留、采购在途、外协在途、待检和库存预警；订单与生产页面只显示与本单有关的摘要和跳转链接。

## 七、共用接口与一致性

新增接口按资源划分：

- `/api/sales-orders`：订单列表、创建、修改、确认、取消和变更。
- `/api/sales-orders/candidates`：可加入订单的图纸任务与报价状态。
- `/api/items`：统一物料与商品档案。
- `/api/suppliers`：供应商档案。
- `/api/supplier-items`：供应商供货关系和价格历史。

现有 `/api/inventory/*`、采购需求和生产履约接口继续复用。新增服务层负责跨模块校验，路由层不直接拼接多份 JSON 数据。

所有正式单据操作使用数据库事务。确认订单、创建生产门樘、采购分配、检验入库和库存记账失败时必须整体回滚，并返回可读的业务错误。前端在页面中央显示错误原因，不只显示通用“操作失败”。

## 八、迁移与兼容

- 现有库存物料迁移到统一商品主档，保留原 ID 或建立稳定映射。
- 现有文本 `default_supplier` 暂时保留为兼容字段；建立供应商主档后转换为供应商关系。
- 现有任务 `quote_status` 作为展示缓存，实际是否已报价以报价记录关联为准。
- 现有 `confirm_status` 不再由列表按钮随意切换；订单正式确认后由系统派生更新，历史记录迁移前仍可读取。
- 现有采购、库存和基础资料组件迁移到独立路由，后端数据不复制。

## 九、实施阶段

### 阶段一：工作台与订单确认骨架

- 新增业务管理菜单、路由和工作台导航。
- 将现有采购、库存、基础资料组件迁移到独立入口。
- 建立销售订单、门樘明细、收款节点和操作记录数据表。
- 完成候选图纸、订单草稿、正式确认和订单列表。

### 阶段二：主数据升级

- 升级物料与商品模型。
- 新增供应商主档、供应商供货关系和双向维护界面。
- 完成现有物料和默认供应商兼容迁移。

### 阶段三：单据链贯通

- 订单确认接入生产待下达。
- 采购需求自动推荐供应商并支持跨订单合并。
- 到货、检验、入库、领料和成品出入库统一追溯。
- 接入收款节点和发货授权放行。

### 阶段四：看板与分析

- 增加订单、采购、库存角色看板。
- 增加交期风险、缺料、逾期采购和库存预警。
- 增加供应商价格、交期和质量分析。

## 十、验收标准

- 可以从同一客户的多个图纸任务创建订单草稿，未报价时不能正式确认。
- 正式确认保存报价和图纸快照，并进入生产待下达；未终审门樘不可下达。
- 一张订单多樘门、多数量下达后均可独立追踪生产编号。
- 商品、供应商和供货关系只维护一份数据，可双向查看。
- 多订单需求可合并采购，采购数量仍能追溯到原需求和门樘。
- 到货未检验不增加可用库存；检验入库、领退料、调拨和报废均有不可变流水。
- 生产、采购和库存页面不重复创建同一业务单据。
- 所有关键失败均显示具体业务原因，事务失败不留下半成品数据。
- 桌面页面无需横向拖动即可完成核心操作，窄屏下使用折叠详情而非压缩字段。
