# 经营管理修复第 1 批：库存一致性

状态：待用户审核。本文只描述库存修复，不代表业务代码已经修改。

## 范围与顺序

经营管理审查发现的问题分批处理，避免一次改变多个独立业务边界：

1. 半成品库存扣减、仓库归属与筛选一致性（本文）。
2. BOM 部件工序使用工艺配置、计件单价与真实人员状态。
3. 工资审批边界与订单、工资编辑防丢失。
4. 按现有岗位确定前后端权限；统一菜单、页面与操作入口。

本批不修改工艺、工资、权限、菜单和 CAD；不删除或重写已有库存流水。

## 保留的业务规则

- 未完成的门框、门套、门扇仍是半成品，可以记录半成品入库。
- 库存位置、在库数量与加工完成状态分开，不以入库推断加工完成。
- 不要求为每个非标门尺寸新建物料主档。
- 成品入库继续使用现有成品质检流程，本批不改变其准入条件。
- 不把不同计量单位的数量相加。

## 已确认的问题

当前半成品入库记录仓库和库位，拼装领用则写死为“半成品仓”，不记录库位。
库存总览按仓库和库位分别汇总，领用无法冲抵对应入库记录。
隔离用例显示：领用前 4 件，领用后门樘可用量为 0，而库存总览仍显示 4 件。

总览的仓库归属和前端筛选使用“同名或同类型”匹配，可能把同类型的不同仓库混在一起。
搜索只过滤公共物料，不过滤订单追踪库存；追踪库存超过 24 项时被直接截断。

## 方案比较

- 只按部件合计：可以修正总数，但丢失分仓库、分库位信息，不采用。
- 重写历史流水：可以统一库位，但会改变历史凭据，不采用。
- 新流水明确来源，旧流水只读兼容：保留追溯和库位信息，推荐采用。

## 新领用规则

1. 以门樘、技术版本、部件为库存主体，以仓库和库位为实际库存位置。
2. 拼装领用读取各位置的剩余半成品，按入库时间、流水 ID 顺序扣减。
3. 一个部件存放在多个位置时，生成多条领用流水，每条保留真实来源仓库和库位。
4. 数量检查和写入在同一数据库事务中完成；不足时不写入任何领用流水。
5. 保留现有重复领用检查。领用不修改加工状态，也不重排工序。

这是系统自动扣账规则，不宣称实物一定按先进先出搬运；人工指定来源库位的功能不在本批新增。

## 历史数据兼容

- 新旧流水使用同一套位置余额计算，避免生产页和库存页各自算一套。
- 旧的无库位领用先抵扣同名仓库的位置余额，按入库时间和流水 ID 顺序处理。
- 对已知旧写法“半成品仓”的无库位领用，若该仓库不足，剩余量在同一门樘、版本、部件的其他位置按相同顺序抵扣。
- 实际来源无法从旧数据精确恢复，上述仅是兼容性分摊；响应应标明该主体存在历史来源推断。
- 明确记录了库位的领用不跨位置冲抵。
- 负余额或超额领用不静默丢弃：保留异常标记，不把负数显示为可用库存。
- 不使用其他门樘、其他技术版本或其他部件的库存填补缺口。

## 仓库归属与界面行为

- 先按仓库名称精确匹配真实仓库；不再因为类型相同就归入第一个仓库。
- 无精确名称匹配时，只有同类型仓库恰好一个才允许兼容归属，并标明推断。
- 同类型存在多个候选时保持未匹配，在“全部仓库”可见，不计入任意单仓指标。
- 订单追踪库存响应增加可空的 `warehouse_id`，前端按 ID 筛选单仓，不按类型筛选。
- 搜索同时作用于公共物料和追踪库存；追踪库存匹配生产编号、部件名称、门型、规格、客户、项目。
- “只看低库存”仅适用于设有安全库存的公共物料，开启时不展示无安全库存标准的订单追踪库存。
- 取消超过 24 项的静默截断，至少提供全部追踪记录的可访问方式。
- 列表键包含版本、部件、仓库、库位，避免同一部件分库位记录的 React 键冲突。
- 仓库卡片的公共物料数量和订单追踪数量分别显示，不用其中一个覆盖另一个。

## 实现边界

- 共用余额计算放在现有库存服务边界内；履约的半成品查询和领用复用它。
- 继续使用现有库存流水表，本批不迁移数据库结构。
- 前端接口字段采取增量兼容，不移除现有名称、规格、单位与数量字段。
- 历史推断与异常提示属于库存记录说明，不替代加工状态。

## 验收

- 单库位入库、全部领用后，生产详情与库存总览均为 0。
- 多库位部分领用、全部领用后，各库位余量和总量一致。
- 在其他名称的半成品仓入库，新领用仍准确记录其来源。
- 已有无库位领用能够正确减少余量，并显示历史来源推断。
- 同类型多仓库不会串仓；无法确定的旧仓库归属不任意分配。
- 两个技术版本、两个门樘、两个部件的余量互不抵扣。
- 重复领用和库存不足不会产生部分写入。
- 搜索能筛选追踪库存，超过 24 项仍能访问所有记录。
- 未完成部件仍允许入半成品仓，入库不改变加工状态。
- 使用隔离临时数据库回归测试，不修改用户当前业务数据。
