# 报价、订单确认与采购到货修正设计

## 目标

本次调整解决四类问题：报价关联图纸后信息错位、CAD 配件遮罩超出或缺失、订单确认信息与附件不足、采购到货数量口径不一致。改动保持现有订单、报价和采购数据可继续读取，不引入独立 CRM 或商品主数据重构。

## 1. 报价关联图纸

### 问题

报价页面选择图纸后会异步读取任务详情和配件价格。当用户连续切换图纸或报价模式时，较早请求可能晚于较新请求返回，从而用旧图纸参数覆盖当前门樘的报价明细。界面上的关联图纸标签来自当前选择，而宽、高和品名来自旧请求，因此出现信息对不上。

### 设计

- 每个门樘报价组维护独立请求序号。
- 发起图纸回填、报价模式切换或门套单价重算时递增请求序号。
- 响应返回后同时校验请求序号和当前 `taskId`，只有最后一次有效请求可以更新明细。
- 宽、高、产品、门型、开向、面积和配件全部从同一次任务详情快照生成，不混用任务列表摘要。
- 增加竞态回归测试，模拟旧请求后返回，确保不会覆盖新选择。

## 2. CAD 配件遮罩与吊脚

### 配件遮罩

遮罩继续优先采用块内真实闭合外轮廓。现有块若包含引线、标注辅助线或离群点，不再直接对全部几何点计算凸包。

处理顺序：

1. 收集块内可见几何并展平曲线。
2. 优先选取面积最大的有效闭合主体轮廓，但排除明显属于孔位的小闭合图形。
3. 没有完整闭合主体时，按主体点云的稳健边界剔除极端离群点，再生成主体凸包。
4. 只有无法得到有效主体时才回退到矩形包围盒。

遮罩仍位于专用遮罩图层，并保持在门板填充之上、配件块之下。新增带引线拉手块测试，验证遮罩不再包含引线区域，并覆盖配件主体。

### 吊脚

- 吊脚高度允许为 `0`，只禁止负数或非数字。
- 选择吊脚时不再把 `0` 判定为未填写。
- 平移门、地弹簧门和天弹簧门已有默认吊脚值保持不变，用户仍可按允许规则修改。

## 3. 订单确认数据模型

### 订单头

在现有客户、项目、收货地址等字段基础上增加：

- 客户联系电话
- 商品类别

客户名称、项目名称、收货地址、联系电话和商品类别提供历史候选。候选值由已有订单去重聚合，输入框聚焦时即可展开选择，同时允许输入新值。新值在订单保存后自然进入后续候选，不额外维护重复字典。

### 门樘明细

每条门樘明细统一展示并保存：

- 产品名称
- 门型
- 宽、高
- 开启方向
- 颜色
- 门套类型
- 主门款式
- 锁具
- 拉手
- 铰链
- 材质
- 商品行备注
- 数量、单位、单价

关联终审图纸时从同一图纸快照自动生成上述字段。对历史订单，优先从已有 `drawing_snapshot.params` 推导缺失字段；手工订单允许直接编辑。已有订单表字段保持兼容，新增技术字段使用独立明细 JSON 保存，避免为每个后续扩展字段持续修改表结构。

### 附件

订单附件分四类：

- 门类图纸
- 客户签字图纸
- 报价单签字图纸
- 拆分图纸

每类允许多张图片，支持拖放、点击选择、缩略图预览和删除。附件不是订单确认必填项。文件保存到订单附件目录，数据库只保存分类、原文件名、存储路径、大小、上传人和上传时间。删除草稿附件时同步删除文件；已确认订单附件保留追溯记录。

上传限制：仅图片格式，单文件大小采用服务端统一限制；文件名由服务端生成，禁止使用用户文件名作为磁盘路径。

## 4. 订单确认界面

- 移除顶部“草稿、已确认、履约中、交期风险”四块大统计卡。
- 将状态筛选合并进搜索工具栏，使用紧凑分段筛选并显示数量。
- 左侧订单列表行展示订单号、客户/项目、状态、首樘门型、宽×高、总门樘数、总额和交期。
- 多条不同门樘时显示首条摘要和“另有 N 项”，避免列表过高。
- 详情区保持订单头、门樘明细、价格、收款和履约追溯的分区结构。

## 5. 采购到货数量口径

### 问题

采购单明细中的 `received_quantity` 当前主要在检验入库后更新，而采购到货单在登记时已经占用了可登记数量。前端用已入库数量计算“剩余到货”，会把待检数量再次提交；后端按全部已登记到货单校验后判定可登记数量为零。

### 统一口径

- `registered_quantity`：所有未取消到货单中已经登记的数量，包含待检。
- `inbound_quantity`：检验合格或让步接收并已入库数量。
- `pending_inspection_quantity`：已登记但尚未完成检验的数量。
- `remaining_receivable_quantity`：采购数量减去取消数量和已登记数量。

采购订单详情接口直接返回以上派生字段。前端“登记全部剩余到货”只提交 `remaining_receivable_quantity`。

当可登记数量为零：

- 存在待检数量时显示“已全部登记，等待检验”；
- 已全部完成时不显示到货操作；
- 不再发起数量为零或重复到货请求。

后端超量错误返回物料名称、采购数量、已登记数量、待检数量和本次最多可登记数量。

## 6. 兼容与测试

- 数据库启动时增量添加订单头字段、门樘技术详情和附件表，不删除旧字段。
- 历史门樘技术信息由图纸快照回填展示；没有快照的字段显示“未填写”。
- 附件上传、删除和订单读取分别测试。
- 报价测试覆盖异步竞态和模式切换。
- CAD 测试覆盖带引线块和已有多边形块。
- 吊脚测试覆盖 `0`、正数和负数。
- 采购测试覆盖首次登记、待检期间再次登记、部分到货、检验入库及超量拦截。
- 前端执行 lint、TypeScript 和正式构建，后端执行相关 pytest 集合。

## 非目标

- 本次不建设独立客户 CRM。
- 本次不建设商品类别主数据维护页面。
- 本次附件不要求电子签章或版本审批。
- 本次不改变采购检验与正式入库的业务分离逻辑。
