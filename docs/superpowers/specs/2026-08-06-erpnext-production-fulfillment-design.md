# ERPNext 生产履约重建设计

## 目标

停止扩展当前项目内的自建生产履约模块。保留现有门厂系统作为订单确认与技术资料系统；从新的生产订单开始，由 ERPNext 作为客户、供应商、物料、仓库、库存、采购、生产、质检和发货的唯一准账系统。

旧生产数据不迁移。当前项目中的历史生产履约数据仅保留查询价值，不参与新的订单履约流程。

## 系统边界

门厂系统负责：

- 报价、图纸录入、CAD 出图、初审、终审和销售订单确认。
- 冻结 DXF、PDF、报价单、订单参数和图纸版本。
- 销售点击“下达生产订单”后，创建并追踪 ERPNext 同步任务。
- 展示 ERPNext 回传的阶段摘要和单据链接。

ERPNext 负责：

- 客户、供应商、物料、单位、仓库和库存台账。
- 销售订单、BOM、生产计划、物料请购、采购订单、采购入库。
- 工单、工序、领料、完工入库、质量检验、发货单。
- 标准权限、审批、审计记录和标准报表。

## 标准业务流程

1. 图纸终审通过后，销售在门厂系统确认并下达生产订单。
2. 门厂系统冻结资料，并以幂等方式自动创建 ERPNext 销售订单草稿。
3. ERPNext 技术人员为该订单专用成品物料建立、确认并提交 BOM。
4. ERPNext 根据 BOM 创建生产计划和物料请购。
5. 采购根据物料请购创建采购订单；到货后通过采购入库单进入仓库。
6. 生产计划创建工单，仓库按工单执行领料或转移到在制品仓。
7. 生产人员按工单和工序执行报工，完成后生成成品入库。
8. 质检合格的成品进入待发货；销售或仓储创建发货单并完成交付。
9. 门厂系统接收或定时查询 ERPNext 阶段，并显示为待 BOM、待料、生产中、待质检、已入库或已发货。

## 订单同步模型

每次下达创建一个可重试的同步任务。同步任务拥有门厂系统订单号、终审任务 ID、冻结版本和幂等键；同一冻结版本不得重复创建 ERPNext 单据。

ERPNext 草稿包含：

- 客户：按门厂系统客户编码查询或创建。
- 销售订单：价格允许为零，报价不作为生产前置条件。
- 订单专用成品物料：编号形如 `DOOR-YYYYMMDD-序号`，避免不同尺寸、门型和配置共用 BOM。
- 自定义字段：门厂订单号、图纸任务号、冻结版本、门型、尺寸、开向、交期、销售备注和源系统链接。
- 附件：冻结 DXF、PDF、报价单及参数 JSON。

技术人员仅在 ERPNext 中维护 BOM；门厂系统不再维护第二套生产 BOM、库存和采购台账。

## 部署设计

同一腾讯云服务器上部署，但使用两个独立 Compose 项目和数据卷：

- `door-erp`：保持现有应用、数据库和备份策略。
- `erpnext`：使用官方 Frappe Docker 生产配置，独立 MariaDB、Redis、后台队列、站点文件和备份目录。
- Nginx：原域名继续转发门厂系统，`erp.<域名>` 转发 ERPNext；只有 Nginx 暴露 80 和 443。
- 内部集成：门厂后端以 ERPNext API Key/Secret 调用 API，密钥仅保存在服务器环境变量中。

部署前必须检查同机 CPU、内存和剩余磁盘。服务器不足时，ERPNext 可整体迁移到新服务器，门厂系统不需要更改业务代码。

## 可靠性与安全

- 同步使用 Outbox 任务表，记录请求摘要、目标单据号、状态、重试次数和脱敏错误信息。
- 所有创建请求都携带幂等键；网络超时后先查询 ERPNext 的来源字段，不盲目重复创建。
- 附件同步失败不得丢弃原始冻结文件；订单草稿保持“待补附件”状态并可重试。
- ERPNext 访问密钥不返回浏览器、不写入前端状态或日志。
- 现有门厂系统与 ERPNext 均保留独立的数据库和文件备份。

## 第一阶段范围

包含：ERPNext 独立测试站点、基础主数据、销售订单草稿自动创建、冻结附件上传、人工 BOM、标准物料请购、采购、入库、工单、领料、完工入库、成品质检和发货验证。

不包含：旧数据迁移、财务、应收应付、工资、成本核算、激光/折弯图自动化，以及自建生产履约页面与 ERPNext 的双向细粒度实时同步。

## 验收标准

使用一樘真实门完成一次端到端演练：

1. 门厂系统自动创建 ERPNext 销售订单草稿及附件。
2. 技术人员确认 BOM。
3. BOM 可生成物料请购并建立采购订单。
4. 到货、入库和领料后库存台账正确。
5. 工单可排期、执行并完成成品入库。
6. 成品质检合格后可创建发货单。
7. 门厂系统可读取并显示 ERPNext 当前履约阶段。
