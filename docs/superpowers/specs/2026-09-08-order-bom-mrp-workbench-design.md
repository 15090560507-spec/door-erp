# 订单确认、整单 BOM 与轻量 MRP 工作台设计

## 1. 文档状态

- 日期：2026-09-08
- 状态：已完成业务讨论，待用户审阅
- 目标版本：第一版轻量 MRP
- 实施原则：底层数据结构按完整 MRP 的扩展方向设计，第一版只启用当前工厂实际使用的规则
- 权限边界：本阶段不扩展角色权限体系，沿用现有登录和访问控制

本设计替代此前生产物料设计中“BOM 仅手工录入、不自动生成”的限制。历史单据继续兼容，自动 BOM 仅对新确认订单和主动触发重新生成的旧订单生效。

## 2. 目标与非目标

### 2.1 目标

建立一条共用单据链：

`已终审图纸 + 对应报价 -> 订单确认 -> 门樘生产编号 -> 整单 BOM -> 库存/采购/工作包 -> 质检 -> 成品入库`

第一版需要实现：

1. 新建订单时关联同一客户的已终审图纸，并自动带入对应报价和业务字段。
2. 每樘门生成独立生产编号、技术快照、BOM 和执行记录。
3. 根据已确认参数自动生成可核对的基础 BOM，缺失数据不阻止其他分组生成。
4. 将原门框加工能力保留为整单 BOM 的加工模块，结果回写 BOM。
5. BOM 发布后自动产生库存预留、采购需求和车间工作包。
6. 支持并行工作包、依赖判断、异常处理和整单进度汇总。
7. 重构经营管理页面，使订单、下料、生产、采购、库存和基础资料使用统一、高效的工作台布局。
8. 治理页面切换、重页面加载、长列表和弹窗定位问题。

### 2.2 非目标

第一版不实现：

- 基于设备、班组能力和有限产能的自动排产优化
- 完整财务总账、应付、成本会计和工资核算
- 自动供应商比价或采购审批流
- 条码、扫码枪、批次和高级库位策略
- 对所有历史订单批量自动生成 BOM
- 新的细粒度角色权限体系

这些能力的数据接口应预留，但不能增加第一版的操作复杂度。

## 3. 总体方案

采用“共用单据链 + 模块化 BOM”的轻量 MRP 方案，不创建一套与现有生产履约平行的新系统。

```text
终审图纸 ─┐
          ├──> 销售订单 ──> 门樘生产编号 ──> BOM 版本 ──> BOM 明细
报价单 ───┘                                             │
                                                       ├──> 库存预留/领料
                                                       ├──> 采购需求/到货
                                                       └──> 工作包/工序依赖
                                                                  │
                                                                  └──> 质检 -> 成品入库
```

设计遵循以下原则：

- 来源可追溯：订单保存关联图纸、报价及确认时快照。
- 门樘可追溯：采购可以合并，生产、质检、入库和执行记录仍按门樘追踪。
- 发布不可覆盖：订单确认快照和已发布 BOM 不允许静默修改。
- 异常优先：缺项、缺料、延期和变更独立显示，不把异常藏在百分比中。
- 实际事件驱动：采购和生产进度由单据事件计算，不允许手工填写进度百分比。
- 正常自动流转：执行人提交完成后，整单负责人只处理异常和最终完工。

## 4. 订单确认

### 4.1 页面结构

订单确认采用“列表 + 摘要 + 独立编辑页”：

- 列表页负责搜索、筛选、状态判断和快速进入。
- 右侧摘要显示客户、交期、金额、门樘、来源和异常。
- 新建和复杂修改进入独立编辑页，避免在狭窄抽屉中编辑长表单。

### 4.2 新建方式

默认新建方式为“关联图纸/报价”：

1. 打开来源选择器。
2. 搜索已终审图纸，可按客户、项目、订单号、门型、尺寸和终审日期筛选。
3. 允许一次选择同一客户的多张图纸；不同客户不能进入同一订单。
4. 系统为每张图纸匹配最新有效报价。
5. 带入后仍可调整订单草稿字段。

同时保留“手工新建”，用于没有前置图纸或报价的特殊订单。手工订单可以保存草稿，但缺少必要技术资料时不能进入 BOM 发布。

### 4.3 自动带入字段

订单头至少带入：

- 客户、项目、订货单位和联系信息
- 订单日期、预计交期、业务员
- 收货地址、备注和收款节点模板
- 报价币种、折扣和含税设置

订单行至少带入：

- 来源图纸 ID、终审版本和报价 ID
- 产品名称、门型、材质、颜色
- 宽、高、数量和开启方向
- 门板、门框、包套、玻璃和五金摘要
- 单价、计价方式、面积、金额和报价备注

订单行允许编辑数量、交期、单价和业务备注。会影响生产结构的参数应通过来源图纸修改后重新关联，或在订单确认后走生产变更单。

### 4.4 状态

- `草稿`：可编辑，可更换来源。
- `待确认`：必填项完整，等待确认。
- `已确认`：生成门樘生产编号和基础 BOM。
- `履约中`：任一门樘进入采购、领料或生产。
- `已完成`：全部门樘已完成并进入成品状态。
- `已取消`：保留历史，不参与后续计划。

异常不混入主状态，独立使用标签：缺报价、图纸版本变化、BOM 未发布、缺料、采购延期、工作包阻塞和变更待处理。

### 4.5 确认结果

订单确认时先在销售订单库的同一事务内：

1. 固化订单头和订单行快照。
2. 创建一条带幂等键的履约生成任务。
3. 写入订单时间线和生成状态。

订单库提交后，系统立即执行履约生成任务，在履约库的一个事务内：

1. 按订单行数量创建独立门樘生产编号。
2. 为每樘门保存生产技术包快照。
3. 创建 `草稿 V1` 基础 BOM 生成记录。
4. 记录销售订单、订单行和门樘之间的稳定关联。

两个数据库不能使用一个本地 SQLite 事务，因此跨库一致性采用可重试任务而不是伪造分布式事务。履约库以销售订单 ID 为唯一幂等键；生成失败时订单保持已确认并显示具体错误，可自动或手工重试，不会重复创建门樘。

重复点击确认必须保持幂等，不得重复创建门樘或 BOM。

## 5. 整单 BOM 工作台

### 5.1 导航与入口

“下料”位于“订单确认”之后。新页面以整单 BOM 为主，原门框加工功能不再是独立业务入口，而是 BOM 详情内的“门框加工”模块。

工作台顶部显示：待生成、待核对、资料缺失、缺料风险、已发布和发生变更数量。

主列表显示：

- 订单号、客户、项目和交期
- 门樘数量和当前选中生产编号
- BOM 完成度、缺项数和当前版本
- 库存满足情况和待采购数量
- 风险状态和最近更新时间

### 5.2 BOM 分组

第一版使用单层明细加业务分组，不强制用户维护复杂多层树：

1. 门框与门槛
2. 门扇与板材
3. 骨架与型材
4. 门套、门头和门柱
5. 玻璃与装饰线条
6. 锁具、拉手、合页和开启机构
7. 外购件与花件
8. 辅料与耗材
9. 包装材料
10. 外协加工

数据模型保留 `parent_item_id` 和 `bom_level`，后续可扩展半成品和多层 BOM，但第一版界面默认不展示复杂层级。

### 5.3 BOM 明细字段

- 物料编码、名称和商品主档关联
- 分组、规格、材质、颜色和图号
- 理论数量、损耗率、计划数量和单位
- 生成来源：规则、门框加工、复制或人工
- 来源参数和来源规则版本
- 匹配状态：已匹配、待确认、缺少资料
- 供应方式：库存、采购、自制或外协
- 对应工序、工作包类型和前置依赖
- 建议供应商、预计采购周期和需求日期
- 图纸、DXF 或附件
- 核对状态、异常原因和备注

### 5.4 自动生成规则

生成服务读取已确认技术快照，根据产品名称、门型、尺寸、门框工艺、门板布局、包套、玻璃、颜色、五金和数量执行规则。

规则输出包括：

- BOM 分组和候选商品
- 理论数量及计算过程
- 默认损耗率和计划数量
- 默认供应方式、工序和工作包类型
- 匹配状态与明确警告

生成采用“可部分成功”原则：

- `已匹配`：规则和商品资料完整，可批量核对。
- `待确认`：数量可计算，但规格、损耗或商品映射需要确认。
- `缺少资料`：保留占位明细，并说明缺少的字段或主档。

一项失败不得使整樘门返回空 BOM。接口返回成功明细和结构化警告列表。

### 5.5 门框加工模块

门框加工模块自动读取当前门樘的门洞尺寸、框宽、门槛、工艺和数量：

- 生成门框零件、长度、角度、开槽和端部加工数据。
- 提供现有 2D 展开和综合 DXF 导出。
- 结果写回“门框与门槛”分组，并记录生成器和模板版本。
- 用户不再重复填写订单号、门型和基础尺寸。
- 门框加工异常只阻止相关分组核对，不影响其他分组继续处理。

### 5.6 BOM 版本

- 自动生成后为 `草稿 V1`。
- 草稿允许编辑、重新匹配和局部重算。
- 发布前必须处理所有阻断级缺项。
- 已发布版本不可直接覆盖。
- 生产变更单创建下一草稿版本，并显示新增、删除、数量变化和规格变化。
- 新版本发布前计算对库存预留、采购、已领料和已加工件的影响。
- 相同参数的多樘门可引用同一 BOM 模板，但每樘门保留独立 BOM 版本和执行状态。

### 5.7 高频操作

- 批量确认已匹配项目
- 仅查看异常或待确认项
- 从相似门型复制 BOM
- 保存为规则模板
- 批量修改供应方式、工序或供应商
- 自动合并同规格采购需求
- 一键生成库存预留、采购需求和工作包

## 6. 物料、采购与库存联动

### 6.1 物料需求

BOM 发布后，为每条有效明细生成物料需求。数量口径为：

`计划数量 = 理论数量 × (1 + 损耗率)`

`缺料数量 = max(计划数量 - 已预留数量 - 已采购未入库数量, 0)`

金额和数量统一使用定点小数，禁止以浮点数直接参与库存和成本计算。

### 6.2 采购需求池

- 缺料或指定采购物料进入采购需求池。
- 支持按供应商、商品、规格、交期合并采购。
- 合并后仍保留需求分配明细，可反查订单、门樘和 BOM 版本。
- 状态由采购单和收货事件计算：待询价、待下单、已下单、部分到货、已到齐、来料检验和可领用。
- 采购到货后先由仓库逐项确认数量，再进入来料检验和入库。

### 6.3 全厂库存

仓库是全厂统一库存，不从属于某个订单。库存至少区分：

- 现存数量
- 已预留数量
- 可用数量
- 在途数量
- 待检数量

生产领料按 BOM 和工作包办理出库，不要求领料人二次确认。系统支持部分入库、部分领料、退料和替代料审批记录。

### 6.4 一致性

BOM 发布、库存预留、采购到货、领料和退料必须由统一领域服务处理，并在数据库事务内同时更新需求、预留、余额和流水，避免页面分别计算出不同结果。

## 7. 工作包与车间进度

### 7.1 工作包生成

发布 BOM 后，根据明细的供应方式、工艺路线和门型模板生成工作包。工作包包含：

- 订单、门樘生产编号和 BOM 版本
- 工序、计划数量和执行班组
- 投入物料、图纸、DXF 和技术要求
- 计划开始、计划完成和标准工时
- 前置工作包和物料齐套条件
- 完成数量、报废数量、实际工时和异常

### 7.2 状态与并行规则

- `待物料`：所需物料尚未齐套。
- `待前序`：依赖工作包未完成。
- `可执行`：物料和前置条件均满足。
- `进行中`
- `待确认`
- `已完成`
- `异常`
- `返工中`

没有依赖关系的工作包可以并行。例如门框下料、门板备料和五金采购可同时执行。系统只限制真实依赖，不要求用户逐个点击整条流程。

### 7.3 执行与管理

执行工作台默认只显示可执行和进行中的工作包，支持批量开始和批量提交。提交时记录合格数量、报废数量、工时、照片和备注。

正常完成自动推动后续状态。整单负责人重点查看：

- 缺料和采购延期
- 阻塞时间最长的工作包
- 交期风险
- 质检不合格与返工
- 订单变更影响
- 待最终完工订单

### 7.4 进度口径

采购、库存和生产进度均由实际事件汇总，不提供手工百分比输入：

- 采购进度来自采购单和到货数量。
- 备料进度来自预留和领料数量。
- 工序进度来自工作包完成数量。
- 整单进度按门樘和关键里程碑汇总。

## 8. 基础资料

商品信息与“供应商及其产品”采用一个商品主档和多条供货关系，避免维护重复商品。

### 8.1 商品主档

- 商品编码、名称、分类、规格和单位
- 材质、颜色和技术属性
- 默认损耗率、默认供应方式和默认工序
- 图纸、图片和说明
- 是否启用及历史版本

### 8.2 供应商供货关系

- 商品 ID、供应商 ID 和供应商商品编码
- 采购单位、换算关系和最小采购量
- 参考价、税率和币种
- 标准交期、首选级别和是否启用

一个商品可关联多个供应商；一个供应商也可供应多个商品。BOM 始终引用内部商品，采购单再选择具体供货关系。

### 8.3 规则模板

自动 BOM 规则独立于商品主档，按以下条件匹配：

- 产品、门型和工艺
- 尺寸区间和数量
- 门板、门框、包套、玻璃与五金配置
- 生效日期和规则版本

规则输出商品、数量公式、损耗、工序和供应方式。规则修改不追溯覆盖已确认订单。

## 9. 数据模型

优先扩展现有领域对象，不创建与履约中心平行的第二套 BOM 表：

### 9.1 订单来源与快照

- `sales_order_door_lines`：继续保存订单与终审图纸、报价的关联及确认快照
- `sales_orders`：增加履约生成状态、错误、重试次数和履约订单关联
- `fulfillment_orders`：增加销售订单来源关联
- `fulfillment_door_units`：继续承载每樘门的独立生产编号，并增加销售订单行关联

### 9.2 BOM

- `fulfillment_technical_packages`：作为 BOM 版本头
- `fulfillment_components`：作为 BOM 明细
- `fulfillment_bom_generation_runs`：记录自动生成批次
- `fulfillment_bom_generation_warnings`：记录缺项、歧义和阻断错误

BOM 明细预留 `parent_id`、`bom_level`、`source_type`、`source_rule_version` 和 `source_payload_json`，支持后续多层 BOM 和规则审计。现有手工技术包按 `legacy_manual` 来源迁移，原 ID 和执行记录保持不变。

### 9.3 计划与执行

- `material_requirements` 与 `material_requirement_items`
- `inventory_reservations` 与 `inventory_transactions`
- `purchase_demands` 与 `purchase_demand_allocations`
- `fulfillment_work_packages` 与 `fulfillment_work_package_dependencies`
- `fulfillment_events`
- `fulfillment_changes` 及变更影响明细

所有下游记录必须携带 `door_unit_id` 和 `technical_package_id`；采购合并表通过分配表保留来源。

## 10. 接口边界

按领域拆分服务，避免在页面路由中复制业务计算：

- 订单来源查询与订单确认服务
- 门樘拆分和生产编号服务
- BOM 规则生成与版本服务
- 门框加工适配器
- 物料需求与库存分配服务
- 采购需求合并与到货服务
- 工作包编排与状态服务
- 进度汇总与异常查询服务

关键写操作接受幂等键。前置条件失败返回 HTTP 409 和可直接展示的中文原因；字段错误返回 HTTP 422，并返回字段路径、输入值和修正建议。

## 11. 经营管理 UI

### 11.1 导航

左侧导航按业务阶段排列，经营管理展开顺序为：

1. 订单确认
2. 下料
3. 生产管理
4. 采购管理
5. 库存管理
6. 基础资料

经营管理支持折叠，进入子页面时自动展开。常用页面支持固定到侧栏上方。

### 11.2 通用页面框架

经营管理页面统一使用：

1. 标题、上下文和主要操作区
2. 紧凑关键指标带
3. 搜索、筛选和视图切换区
4. 主数据区

高频处理使用列表与详情；复杂编辑进入独立页面；异常使用抽屉；确认、发布等关键操作使用居中弹窗。页面分区不使用层层嵌套卡片。

### 11.3 各页面布局

- 订单确认：订单列表、订单摘要和独立编辑页。
- 下料：订单列表、门樘树和 BOM 明细三段式布局。
- 生产管理：订单进度、工作包和异常页签。
- 采购管理：需求池、采购单和到货跟踪页签。
- 库存管理：库存台账、待入库、待领料和流水页签。
- 基础资料：商品、供应商和规则模板页签。

### 11.4 视觉规范

- 深色窄侧栏、浅灰工作区和高对比白色业务面板。
- 关键文字使用深灰，浅灰仅用于辅助信息。
- 黑色只用于侧栏和少量高优先级命令，不在白色页面零散布置纯黑按钮。
- 蓝色或石墨色用于主要操作；绿、橙、红分别表示成功、风险和异常。
- 荧光黄绿色只用于当前导航和少量关键提醒。
- 面板圆角控制在 6 至 8px。
- 长文本允许换行并提供完整悬停提示。

### 11.5 弹窗和动画

- 弹窗统一通过根节点 Portal 渲染，使用固定定位并在当前视口居中。
- 长弹窗内容独立滚动，标题和底部操作固定。
- 页面内容淡入 140 至 180ms。
- 侧栏折叠 180ms，抽屉滑入 180 至 220ms。
- 进度条和数字仅在首次加载时平滑变化。
- 不对页面根容器做位移动画，避免破坏固定弹窗定位。
- 表格不做逐行复杂入场动画。

## 12. 性能设计

- 效果渲染、DXF 预览和大文件解析按路由延迟加载。
- 离开页面时取消仍在执行的预览和查询请求。
- 图片缩略图懒加载，完整图仅在打开时读取。
- 长列表服务端分页或虚拟滚动。
- 页面切换先渲染稳定骨架，避免旧页面阻塞导航。
- 列表、指标和详情分别缓存，保存后只失效受影响的数据。
- 对慢接口记录服务端耗时、网络耗时和前端渲染耗时。
- 重计算放入后台任务，并显示可恢复的生成状态。

## 13. 异常与一致性

- 缺商品资料：保存可生成明细，并集中展示缺失项。
- 缺报价：订单可保存草稿，不能正式确认。
- 图纸版本变化：提示来源版本差异，不自动覆盖订单。
- BOM 生成失败：指出订单、门樘、分组、规则和输入参数。
- 库存不足：进入待采购或异常，不伪装为已齐套。
- 已采购、领料或加工后发生变更：发布新版前展示影响。
- 重复保存、确认、履约生成、发布和生成工作包：通过幂等键和状态校验防止重复单据。
- 跨订单库与履约库的生成失败：保留订单确认事实和失败原因，通过同一幂等键重试，不回滚或复制已经确认的订单。
- 任一模块加载失败：保留其他已成功加载区域，并提供局部重试。

## 14. 历史数据与迁移

1. 保留现有销售订单、生产订单、BOM、采购和库存表及接口兼容层。
2. 为历史生产订单按需创建门樘记录，不自动重算历史库存。
3. 历史 BOM 标记来源为 `legacy_manual`，仍可查看和执行。
4. 新订单默认走新确认链；旧页面在迁移期读取统一服务。
5. 原门框项目保留查看和导出，主动关联门樘后才写入新 BOM。
6. 数据迁移脚本必须可重复执行，并输出创建、跳过和异常数量。

## 15. 测试与验收

### 15.1 后端

- 同一客户多张终审图纸可以创建一张订单。
- 不同客户来源被拒绝并返回明确原因。
- 报价和技术字段正确固化为订单快照。
- 重复确认不产生重复门樘或 BOM。
- 数量大于一时生成独立门樘生产编号。
- BOM 可以部分生成，并返回结构化缺项。
- 已发布 BOM 不可覆盖，变更生成新版本。
- 门框加工结果正确写回对应 BOM 分组。
- 物料需求、预留、缺料和采购数量计算准确。
- 合并采购仍能按门樘和 BOM 版本反查。
- 没有依赖的工作包可并行，依赖未完成时保持阻塞。
- 重复入库、领料和工作包提交不会重复记账。

### 15.2 前端

- 来源选择、自动带入、编辑、保存和确认流程完整。
- BOM 工作台支持订单、门樘和分组切换。
- 缺项定位到具体字段或 BOM 行。
- 长列表、窄屏和常用桌面分辨率不发生文字遮挡。
- 所有弹窗在滚动后的当前视口居中。
- 经营管理各页面按钮、状态和错误提示一致。
- 页面离开后不继续阻塞导航或更新已卸载页面。

### 15.3 全链路验收场景

选择两张同一客户的已终审图纸，创建并确认订单；系统按数量生成独立门樘和基础 BOM。下料员完成缺项核对和门框加工后发布 BOM，系统形成库存预留、采购需求和可执行工作包。采购分批到货、仓库逐项入库、执行人并行完成工作包，独立质检合格后完成成品入库。全过程可以从订单追溯到门樘、BOM 版本、物料流水和工作包事件。

## 16. 实施拆分

本设计作为一个总体架构，实施分六个可独立验收的阶段：

1. 订单确认重构和来源关联。
2. 门樘数据、整单 BOM、自动生成和门框加工整合。
3. 物料需求、库存预留和采购需求联动。
4. 工作包、依赖关系和车间进度工作台。
5. 经营管理 UI 统一改版和性能治理。
6. 历史数据兼容、全链路联调和上线检查。

每个阶段都必须保持已上线的 CAD、报价、订单和生产接口可用，不允许等全部功能完成后一次性切换。
