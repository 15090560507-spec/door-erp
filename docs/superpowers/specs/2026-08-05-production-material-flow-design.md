# 生产物料闭环与工作台成熟化设计

## 1. 目标

在不影响订单确认阶段、CAD 绘图、报价和效果渲染的前提下，完善生产订单下达后的执行流程：

`生产订单 -> 手工 BOM -> 物料需求与库存预留 -> 排单/下料 -> 采购 -> 仓储入库/领料 -> 生产 -> 质检 -> 成品入库 -> 发货`

本阶段不自动生成 BOM。BOM 仍由技术人员根据生产订单手工填写和确认发布。

## 2. 权限策略

当前阶段暂不区分生产业务权限。所有已登录用户均可查看和操作生产履约的全部功能，包括：

- 生产订单下达、复制、撤回和状态管理
- BOM 编辑与发布
- 物料需求、备料和采购
- 排单、下料和生产工序
- 仓储入库、领料、退料和库存登记
- 质检、成品入库和发货

接口仍必须要求登录，超级管理员专属的用户管理、AI 配置等安全权限不受影响。前后端不得再以 `production.*` 权限隐藏按钮或拒绝生产业务请求。

## 3. 核心业务流程

### 3.1 BOM 发布

1. 技术人员为生产订单手工填写 BOM 草稿。
2. BOM 为空时不能发布。
3. BOM 发布后创建或刷新该订单的物料需求单。
4. 已发布 BOM 的变更必须产生新版本或经过明确的撤回动作，不能静默覆盖已经分配库存的需求。

### 3.2 物料需求与库存预留

库存采用三种数量：

- 现存库存：仓库内实际数量。
- 已预留：已分配给生产订单、尚未领料的数量。
- 可用库存：`现存库存 - 已预留`。

每条 BOM 明细生成一条物料需求明细，记录：

- 需求数量
- 已预留数量
- 缺料数量
- 已采购数量
- 已到货数量
- 已领料数量

缺料计算原则：

`缺料数量 = max(需求数量 - 已预留数量 - 已采购未入库数量, 0)`

BOM 发布时按可用库存自动建立预留。采购到货入库后再次执行分配，优先补足对应采购需求关联的生产订单，再处理其他待分配需求。

库存预留不改变实际库存。只有生产领料时才写入出库流水、减少现存库存并释放对应预留。

### 3.3 采购

缺料明细进入采购需求池，由操作人员勾选后生成采购单，而不是 BOM 发布后直接下单。

- 支持按供应商批量合并多个生产订单的采购需求。
- 采购明细必须关联物料、物料需求明细和生产订单。
- 采购单状态：草稿、已下单、部分到货、已完成、已取消。
- 到货可以分批登记，但累计入库不得超过采购数量。
- 采购入库后自动刷新物料需求、库存预留和订单缺料状态。

### 3.4 排单与下料

- BOM 发布后可以生成综合下料单。
- 缺料时允许保存下料单草稿，但不能正式下发。
- 排单字段包括计划开始、计划完成、生产人、负责人和缺料状态。
- 缺料时允许保存排单，并显示醒目警告；负责人可以明确确认后强制排单。
- 全部物料已预留后，订单备料状态自动变为“已备料”。

### 3.5 仓储

仓储独立于采购，包含：

- 库存余额：现存、预留、可用分别展示。
- 采购入库：从采购单办理，可分批入库。
- 生产领料：按生产订单和需求单领料。
- 生产退料：退回库存并更新需求状态。
- 其他入库与报废。
- 完整库存流水。

领料数量不能超过订单已预留数量；退料数量不能超过该订单累计领料数量。

## 4. 数据结构

采用现有 SQLite 生产数据库的增量建表方式，不修改订单确认阶段的数据结构。

### 4.1 `production_material_requirements`

- `id`
- `order_id`
- `bom_version`
- `status`：待分配、部分备料、已备料、已关闭
- `created_at`
- `updated_at`

### 4.2 `production_material_requirement_items`

- `id`
- `requirement_id`
- `order_id`
- `bom_item_id`
- `material_id`
- 名称、规格、单位等冻结字段
- `required_quantity`
- `reserved_quantity`
- `purchased_quantity`
- `received_quantity`
- `issued_quantity`
- `shortage_quantity`
- `status`

### 4.3 `production_inventory_reservations`

- `id`
- `order_id`
- `requirement_item_id`
- `material_id`
- `quantity`
- `status`：已预留、部分领料、已领料、已释放
- `created_at`
- `updated_at`

### 4.4 采购明细扩展

现有 `production_purchase_items` 增加：

- `requirement_item_id`
- `order_id` 保持并要求准确关联

历史采购单允许上述字段为空。

## 5. 页面结构

生产履约顶部调整为：

1. 生产总览
2. 生产订单
3. BOM 与备料
4. 生产排单
5. 下料单
6. 采购
7. 仓储
8. 质检与成品
9. 发货

### 5.1 订单详情

订单详情继续作为单订单完整工作台，显示：

- BOM 状态和版本
- 需求量、已预留、缺料和采购进度
- 下料单与排单状态
- 生产工序、质检、成品入库和发货状态
- 全过程时间线

### 5.2 跨订单工作台

- BOM 与备料：批量查看待发布 BOM、缺料和备料状态。
- 生产排单：跨订单安排日期、人员和负责人。
- 下料单：集中处理草稿、待下发、下料中和已完成单据。
- 采购：采购需求池和采购单分区展示。
- 仓储：库存余额、采购入库、生产领料和流水分区展示。

所有操作按钮均可见。不能执行时必须显示明确原因，不使用没有说明的禁用状态。

## 6. 接口设计

新增或调整以下接口：

- `GET /api/production/material-requirements`
- `GET /api/production/orders/{id}/material-requirement`
- `POST /api/production/orders/{id}/material-requirement/allocate`
- `POST /api/production/material-requirements/purchase`
- `POST /api/production/orders/{id}/materials/issue`
- `POST /api/production/orders/{id}/materials/return`
- `GET /api/production/inventory/balances`
- `GET /api/production/inventory/transactions`

发布 BOM、采购入库和生产退料后，由后端事务内调用统一的库存分配服务。库存、预留、需求和采购状态必须在同一事务内更新。

## 7. 错误和状态反馈

- 所有创建、保存、发布、入库、领料、退料操作显示成功或失败弹窗。
- 前置条件失败返回 HTTP 409，并包含可直接展示的中文原因。
- 数量非法返回 HTTP 400，并说明允许范围。
- 页面加载失败不清空已经加载成功的其他模块。
- 重复提交使用后端状态校验，避免重复采购、重复入库和重复领料。

## 8. 测试范围

后端自动测试至少覆盖：

- 所有登录用户都能访问和操作生产履约接口。
- 未登录仍返回 401。
- BOM 发布创建物料需求。
- 库存充足时正确建立预留且不产生缺料。
- 库存不足时正确计算缺口。
- 多订单不会重复占用同一可用库存。
- 采购需求生成采购单并保持关联。
- 分批采购入库更新已到货和预留。
- 领料减少实际库存并释放预留。
- 超量采购入库、领料和退料被拒绝。
- 缺料时下料单不能正式下发。
- 原 CAD、报价、效果渲染和订单确认测试保持通过。

前端验证至少覆盖生产构建、定向 ESLint、关键状态按钮和错误提示。

## 9. 非本阶段范围

- 不自动生成 BOM。
- 不实现供应商比价和采购审批。
- 不实现库位批次、条码和扫码枪。
- 不实现复杂 MRP、生产能力排程和财务应付。
- 不修改 CAD、报价和效果渲染业务逻辑。
