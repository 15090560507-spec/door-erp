# AutoCAD 原生 JPG 打印节点设计

## 1. 背景与目标

现有后端使用 Matplotlib 重新解释 DXF 并生成 JPG。该方式虽然能固定输出为 `5940 x 4200`，但它不是 AutoCAD 原生打印，会出现以下问题：

- 部分 `HATCH`、`SOLID`、`WIPEOUT` 或复杂块被错误绘制为大面积黑块。
- CAD 字体被替换，中文可能变成方块。
- 线宽、打印样式和复杂块显示无法保证与 AutoCAD 一致。
- 图纸预览在前端先请求 DXF、再请求 SVG，产生重复等待。

本批次目标：

1. 正式 JPG 必须由 AutoCAD 2022 原生打印引擎生成。
2. 使用 `ORDER_FORM` 外框作为打印窗口。
3. 固定采用用户常用的打印参数。
4. 腾讯云 Ubuntu 继续运行 ERP，不在云端安装 AutoCAD。
5. 当前 Windows 电脑作为打印节点，关机时任务可以安全排队。
6. 网页 CAD 预览恢复为独立的轻量流程，不受正式 JPG 打印影响。

## 2. 总体架构

系统拆分为三个独立单元：

### 2.1 腾讯云 ERP

负责：

- 生成并保存待打印 DXF。
- 创建、查询和管理 CAD 打印任务。
- 向 Windows 打印助手提供受控的任务领取接口。
- 接收并保存打印完成的 JPG。
- 向前端返回打印节点状态、任务进度和下载地址。

腾讯云不负责解释 DXF，也不再使用 Matplotlib 生成正式 JPG。

### 2.2 Windows AutoCAD 打印助手

运行在当前已安装 AutoCAD 2022 的 Windows 电脑上。已确认可执行文件位于：

`D:\Desin all\CAD2022\AutoCAD 2022\accoreconsole.exe`

打印助手负责：

- 定时向腾讯云发送心跳并领取一个打印任务。
- 下载任务对应的 DXF 到独立临时目录。
- 调用 AutoCAD Core Console 和受控 AutoLISP/脚本。
- 检查输出 JPG 是否存在、尺寸是否正确。
- 上传 JPG 或回传结构化失败原因。
- 完成后清理本次任务临时文件。

助手只主动访问腾讯云，不监听公网端口。

### 2.3 前端图纸页面

负责：

- 点击“打印 JPG”时创建原生打印任务。
- 显示“等待节点 / 打印中 / 已完成 / 失败”。
- 显示 Windows 打印节点“在线 / 离线”。
- 打印完成后提供查看和下载。
- “预览 DXF”继续使用轻量 SVG，不等待原生 JPG。

## 3. 原生打印参数

AutoCAD 脚本采用以下固定配置：

- 打印机：`PublishToWeb JPG.pc3`
- 打印样式表：`monochrome.ctb`
- 输出像素：`5940 x 4200`
- 打印区域：窗口
- 窗口范围：DXF 中 `ORDER_FORM` 块的实际外围边界
- 打印比例：布满图纸
- 打印偏移：居中打印
- 图形方向：横向
- 打印对象线宽：启用
- 按样式打印：启用
- 后台打印：关闭，等待文件完全写入后再上传

如果 DXF 中不存在 `ORDER_FORM`，任务直接失败并提示“未找到 ORDER_FORM 图框”，不回退到整张图纸范围，避免错误裁切。

## 4. 打印任务状态

任务状态固定为：

- `queued`：已创建，等待打印节点。
- `claimed`：已被某个节点领取。
- `printing`：AutoCAD 正在打印。
- `uploading`：JPG 正在上传。
- `completed`：打印成功，可下载。
- `failed`：打印失败，可查看原因并重试。
- `cancelled`：尚未执行的任务被用户取消。

任务记录至少包含：

- 任务 ID
- 来源图纸任务 ID
- DXF 文件位置和参数指纹
- 创建人和创建时间
- 打印节点 ID
- 当前状态和更新时间
- 尝试次数
- 失败阶段、错误摘要和日志尾部
- JPG 文件位置、像素尺寸和文件大小

同一图纸参数指纹已有成功结果时可以直接复用；参数发生变化后必须创建新任务。

## 5. 节点在线与离线处理

Windows 打印助手周期性发送心跳。腾讯云根据最后心跳时间判断状态：

- 最近心跳正常：在线。
- 超过规定时间未收到心跳：离线。

离线时：

- 用户仍可提交任务。
- 任务保持 `queued`。
- 页面明确提示“打印节点离线，电脑开机后会自动继续”。
- 不自动改用 Matplotlib 或其他近似渲染器。

打印节点领取任务后设置租约。节点意外退出且租约超时，任务重新回到队列，避免永久卡在“打印中”。每次只执行一个 AutoCAD 打印任务，防止 Core Console 并发冲突。

## 6. 安全设计

- Windows 助手使用独立设备令牌，不使用员工账号密码。
- 设备令牌只能执行心跳、领取任务、下载对应 DXF、更新本任务状态和上传打印结果。
- 腾讯云不需要访问 Windows，不开放 Windows 入站端口。
- 上传结果校验任务租约和节点身份。
- 日志不得记录员工密码、设备令牌或完整授权头。
- 设备令牌通过本地配置或环境变量提供，不提交到 Git。

## 7. Windows 运行方式

首版提供：

- 可在终端手动启动的打印助手。
- Windows 开机自动启动配置脚本。
- 本地配置模板，包括 ERP 地址、设备 ID、设备令牌、AutoCAD 路径和轮询间隔。
- 清晰的运行日志和当前状态。

助手启动时先检查：

- AutoCAD Core Console 是否存在。
- `PublishToWeb JPG.pc3` 是否能被 AutoCAD 解析。
- `monochrome.ctb` 是否能被 AutoCAD 解析。
- 临时目录和输出目录是否可写。
- 腾讯云接口是否可连接。

检查不通过时不领取任务，并向腾讯云报告节点不可用原因。

## 8. CAD 预览性能调整

“预览 DXF”和“打印 JPG”必须完全独立：

### 8.1 预览 DXF

- 前端只调用一次 `/api/generate_cad_preview`。
- 后端在该请求中生成或命中 DXF 缓存，然后转换为轻量 SVG。
- 前端不再为了预览提前调用 `/api/generate_cad` 下载 DXF。
- 预览流程不导入或调用 Matplotlib、AutoCAD 或高分辨率 JPG 流程。

### 8.2 下载 DXF

- 用户点击“生成 DXF”时调用下载接口。
- 若参数指纹与预览一致，后端复用已经生成的 DXF 缓存。

### 8.3 打印 JPG

- 用户点击“打印 JPG”时仅创建后台打印任务。
- 前端不长时间阻塞请求，通过轮询任务状态更新页面。

## 9. 错误处理

错误必须区分阶段：

- DXF 生成失败
- DXF 下载失败
- AutoCAD 启动失败
- AutoCAD 脚本失败
- 未找到 `ORDER_FORM`
- 缺少 PC3 或 CTB
- JPG 未生成
- JPG 尺寸不正确
- JPG 上传失败
- 打印节点离线或租约过期

失败任务保留日志摘要和重试按钮。重试创建新的尝试记录，不覆盖原失败信息。

## 10. 验收标准

### 10.1 原生打印

- 生成过程实际调用 AutoCAD 2022 Core Console。
- 输出 JPG 像素严格为 `5940 x 4200`。
- 打印范围严格来自 `ORDER_FORM` 外框。
- 输出为白底黑线，不出现错误的大面积黑块。
- 中文标题、明细文字和尺寸文字不变成方块。
- 与同一 DXF 在 AutoCAD 图形界面使用相同参数打印的结果进行目视比对，字体、填充、线宽、位置和比例一致。

### 10.2 节点离线

- Windows 助手停止后页面显示节点离线。
- 新任务保持排队且不会丢失。
- 助手恢复后自动领取并完成任务。

### 10.3 预览性能

- 点击“预览 DXF”只发起一次业务请求。
- 首次预览不再因提前下载 DXF而重复等待。
- 已缓存参数再次预览能快速返回。
- 预览期间不会启动 AutoCAD 或高分辨率 JPG 渲染。

## 11. 本批次边界

本批次不包括：

- 在腾讯云 Ubuntu 安装或模拟 AutoCAD。
- 多台打印节点负载均衡。
- DWG 批量打印和多布局打印。
- 用户自定义 PC3、CTB、纸张尺寸或打印方向。
- 用近似服务器渲染作为原生打印失败后的自动回退。

首版固定一台 Windows 打印节点和一套已经确认的打印参数，先保证结果正确、流程可靠。
