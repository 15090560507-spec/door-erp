# 经营管理修复第 2 批：工艺、整门计件与人员状态

状态：实施、隔离验证与 GitHub 推送已完成，代码提交 `34ea5c7`；交付验证见同目录验证记录。

## 已确认规则

- 生产进度仍逐项对应 BOM，部件可以分别指定执行人员。
- 计件按整樘门的每道工序计算，不按部件数或工作包数重复计算。
- 同一道整门工序可手动分配给多名人员；分配合计不得超过该工序总额。
- 不自动平均分，不默认归给最后完工人员，不以拼装人员代替其他工序的计件人员。
- 已发布工序保留配置和价格快照，历史工资不自动改写。
- 人员页面只保留部门、人员、当前工作与真实状态，不增加下一任务、交期、今日完成量和负荷。

## 已复现问题

1. `WorkPackageService.generate_for_package` 使用写死的部件路线，未使用可编辑模板。隔离测试中模板折弯单价为 88，新生成的两个折弯工作包单价仍为 0，模板关联为空。
2. 人员聚合以是否存在未完成分配判断“工作中”；仅已排单的人员也显示工作中。
3. 人员聚合未排除取消订单和旧技术包，会让失效任务继续占用人员。
4. 现有计件草稿以工作包为唯一主体，不能直接承担“一樘门一道工序、多名人员”的总额约束。

## 方案选择

- 独立整门计件汇总 + 部件工作包：生产和计价各有明确主体，可约束多人合计和重复确认，采用。
- 将整门金额挂在某个部件：表结构变化较少，但完成顺序和人员归属会影响计薪，不采用。
- 将整门金额自动分摊到各部件：总额可受控，但违反手动分配要求，且容易产生舍入和返工重复，不采用。

## 1. 工艺配置与部件进度

继续使用现有工艺模板和工作包，不恢复整门大步骤替代 BOM 部件表。

模板工序须明确适用部件组：外皮、骨架、装配总成、包装、其他自制件。新增适用组字段，不根据中文名称猜测适用性。

既有默认模板按以下编码关系兼容，避免一次更改已有工作包的业务编码：

| 整门模板工序 | 部件执行编码 | 默认适用组 |
| --- | --- | --- |
| PANEL_PREP | PREPARE | 外皮、骨架 |
| PANEL_CUT | SHEAR / CUT | 外皮、骨架 |
| BENDING | BEND | 外皮 |
| BODY | WELD | 骨架 |
| SURFACE | SURFACE | 外皮 |
| ASSEMBLY | ASSEMBLY | 装配总成 |
| PACKAGING | PROCESS | 包装 |

剪板和骨架下料在既有 `PANEL_CUT` 配置下归为同一笔整门下料费用。今后需要分别计价时，必须建立两个明确适用组的模板工序，不以同名或近似名称自动合并。

既有 `TECH_PREP`、`FITTINGS_PREP`、`QC_HANDOFF` 继续由生产准备、物料状态和成品质检处理，不在本批复制成部件制造工序或新增计件费用。

- 外皮和骨架路线取各自适用工序；同一部件的前序关系和自制子件到总成的依赖继续保留。
- 去除不适用的中间节点时，沿模板依赖连接最近的适用前序，而不是把后续工序错误释放为无前序。
- 适用范围、工序名称、标准时间、工作中心、质检要求和前序关系在发布时保存快照。
- 新单工作包关联真实模板及步骤；整门单价存在计件汇总快照中，不复制到每个部件的可计薪 `piece_rate` 字段。
- 其他自制件没有匹配配置时，可以沿用原备料/加工路线，但明确显示“工艺未配置”，不臆造单价，不自动生成收费工序。
- 外购材料与配件仍走采购、到货和库存状态，不生成制造或计件工序。
- 模板更新验证重复编码、空白编码、自依赖、未知前序、循环依赖和启用步骤对停用步骤的无效依赖；失败时整单回滚。
- 修改模板只影响此后新发布的生产单，不追改已发布工序。

本批不实现根据剖面工艺自动推断折弯骨架或方管骨架路线；这种路线差异必须由适用配置明确表达。

## 2. 整门计件主体

新增整门工序计件汇总、关联工作包、多人分配明细三类记录，通过增量迁移创建，不改写旧计件表。

- 一条汇总对应一个门樘生产编号和一个明确的计价工序编码；以 `(door_unit_id, billing_operation_code)` 唯一约束防止重复计件。
- 汇总保存模板/版本、单价、单位“樘”、数量 1、总额、相关工作包和完成时间；不使用部件计划数量乘整门单价。
- 金额统一按分存储与校验；输入最多两位小数，拒绝负数、非有限数和静默舍入。
- 发布时冻结配置和相关工作包集合，先显示加工状态；全部相关工作包真实完成后才进入“待分配”。
- 暂停、异常、返工和待检不能满足完成条件。
- 已取消或跳过的相关工作包不视作收费完成；显示“需核对”，不自动计薪。全部跳过也不生成费用。
- 同一工序通过质检后完工，才能进入待分配；重复完工或重复确认不新增费用。
- 零单价明确显示“未设置计件单价”，不自动分配，也不阻止合法生产进度。

## 3. 多人分配与工资连接

生产页在部件表后、拼装人员区域旁增加紧凑的“整门计件”列表，不把它混进每个部件的加工状态。

列表显示工序、加工状态、总额、已分金额、剩余金额和分配入口。分配弹窗只输入人员、金额和说明；人员选择复用在职人员档案。

- 同一人员在一笔工序中只能有一条分配，避免重复选择造成不清晰的金额。
- 可以保存未分完的草稿，显示剩余额度，不自动补足或平均分。
- 确认前再次核对工序完成、人员有效、未取消订单、金额合计不超额和当前修订号。
- 确认允许分配合计小于总额，未分金额不进入工资；确认页面明确列出未分金额。
- 确认在同一事务内完成，重复提交保持幂等；并发旧修订号提交返回冲突并要求刷新。
- 确认后的分配不可直接覆盖或删除；确认后的补分、冲销和费用调整留给后续调整流程，本批不新增调整单。
- 月度计件读取新模式已确认分配，只计确认给该人员的金额；未完成、未确认、取消订单不自动计入新模式工资。
- 新模式以工序全部完成时间所属月份归集；该月份工资已审批或锁定时禁止确认分配，不能通过重新计算绕过。
- 仅为新模式增加上述接入保护，不在本批重构旧模式的全部工资审批权限和历史草稿审核逻辑；这些仍在第 3 批处理。

例如整门焊接为 100 元，张师傅 60 元、李师傅 40 元，产生两条人员分配，但只有一笔 100 元的整门工序总额。分配 60 元、30 元时显示 10 元未分；60 元、50 元时禁止保存或确认。

## 4. 版本与历史兼容

- 既有生产单和计件草稿默认保持旧模式，不自动套用新单价，不自动转成多人分配。
- 新建立的生产单明确启用整门模式；工作包完工时跳过旧的逐工作包工资写入，只通过整门分配计薪。
- 一张门樘不能同时使用两种计件来源。月度查询按模式互斥读取，不能将旧工资草稿与新分配相加。
- 新模式技术变更后，未确认计件汇总转为需核对；发布新版本时更新其版本和工作包集合，保持同门樘同工序的唯一主体，清空未确认分配草稿并保留变更事件，须按新总额重新分配，不能沿用失效完成状态。
- 已确认计件不因新技术版本自动删除、重算或再次计件；涉及已计件工序的新工作标明补加工，默认不自动追加费用。
- 模板价格修改不重算既有快照；新增工序收费由新版本明确产生，不能靠改名为同一工序重复收费。
- 数据迁移只新增表、字段与索引，并提升现有履约 schema 版本；迁移可重复运行，不修改真实历史金额。

## 5. 人员当前工作

人员仍按部门展示，每人显示一项优先任务；这不是下一任务队列，也不表示该人员只有一张分配单。

- 只查询在职人员、有效订单、最新可执行技术包及非终止工作包；旧版本、已完成、已取消工作不再占用人员。
- 有进行中任务时显示“工作中”；待排单/已排单显示“待开工”；待质检显示“待检”；暂停、异常、返工保持各自状态；没有有效工作显示“空闲”。
- 同人多项任务时，优先进行中，再依次异常、返工、暂停、待质检、已排单、待排单，同级按现有顺序和 ID 稳定选择。
- “工作中”人数只统计真正进行中的人员；其他有任务人员不误计为空闲，分别在已有状态中显示，不增加负荷指标。
- 执行人员与计件分配人员是两个职责，不相互覆盖。人员当前工作来自实际执行分配，不来自工资分配。
- 不以职员姓名猜测身份；以员工 ID 为准，对旧执行人编号保留明确编号兼容。

## 范围边界

本批不重设计整个导航、不修改 CAD、库存扣减或客户订单输入字段，不自动迁移旧单计价，不接入付费效果图生成，不修改用户现有账号数据。

新增计件记录仅形成可核对的费用和工资计算来源，不执行付款。

## 验收

1. 新单配置折弯单价 88 元，两个部件折弯完成后只有一笔 88 元整门费用，不产生两笔 88 元旧工资草稿。
2. 工序名称、工作中心、质检与依赖来自匹配配置；已发布快照不随模板更新变化。
3. 相同整门下料配置的剪板与骨架下料只计一次，明确拆开的两个配置才分别计价。
4. 工序未完成、待检、返工、跳过时不能确认费用；重复完成/确认不重复计件。
5. 多人分配支持草稿与未分余额；超额、负数、重复人员、无效人员和并发旧修订均不写入部分数据。
6. 金额到分精确校验，验证 0.10 + 0.20 的边界，拒绝三位小数而非静默舍入。
7. 月度工资只读取已确认新分配，保留旧模式但不双计；已审批/锁定月份不能接收新分配。
8. 技术变更不会携带旧完成状态或自动再次计薪，历史已确认金额保持不变。
9. 待开工、待检、取消订单、旧技术包和离职人员的聚合正确；真正进行中人员才显示工作中。
10. 原部件生产、整门装配、质检和库存回归通过，桌面与手机分配界面无重叠或溢出。
11. 所有数据库与工资验证使用隔离测试数据，不修改用户当前业务记录。
